## Decisions

### D-1 Keep mando at 0.7.1 and radon at 6.0.1

- **Decision**: Keep `mando==0.7.1` and `radon==6.0.1`. Close pull request #4888 only after the ignore rule reaches main.
- **Alternatives considered**:
  - Move radon to a release that accepts mando 0.8. Rejected, because radon 6.0.1 is the newest PyPI release (R40).
  - Keep mando 0.8.2 and remove radon. Rejected, because the radon gate is a documented quality gate (R30). Removing it changes a required gate.
  - Edit only the pin line, as pull request #4888 does. Rejected, because `requirements-dev.txt` is generated by `uv export` (R48). `uv.lock` pins mando 0.7.1 (R18), so the export guard (R17) fails even when pip resolves.
- **Rationale**: The latest Quality Gates run on main passed (R34). The pin matches `uv.lock` (R18) and the locally installed radon metadata (R41).
- **Risk**: Radon 6.0.1 can stay the newest release for a long time. Mitigation: D-2 and D-3 state the removal condition.
- **Human decision required**: No.

### D-2 Ignore mando minor and major updates in the pip update stream

- **Decision**: Add an `ignore` entry for `mando` with `version-update:semver-minor` and `version-update:semver-major`.
- **Alternatives considered**:
  - Use a `versions` range. Rejected, because the Dependabot documentation fetch was blocked (U-2). The repository already uses `update-types` in the npm entry (R45).
  - Comment `@dependabot ignore this minor version` on the pull request. Rejected, because a comment is not reviewed and is not kept in the repository.
  - Add no ignore rule. Rejected, because Dependabot might propose the update again (U-3).
- **Rationale**: The commit classifies the bump as `version-update:semver-minor` (R08). The syntax matches an entry that already exists in the same file (R45). A patch update such as 0.7.2 is still allowed.
- **Risk**: The rule also blocks a future mando minor release that radon might accept. Mitigation: the rule comment and the pin test name the removal condition.
- **Human decision required**: No.

### D-3 Guard the pin with a new test in the existing policy module

- **Decision**: Add `test_pinned_mando_stays_below_radon_limit` to `TestDependabotPolicy`. Update the pip snapshot in the same change.
- **Alternatives considered**:
  - Create a new test module. Rejected, because it repeats the policy reading that the existing module already does.
  - Leave the snapshot unchanged. Rejected, because the complete-policy comparison fails with the new rule (R23).
  - Exclude mando from the comparison. Rejected, because that weakens a guard that the repository relies on.
- **Rationale**: The pin test fails on the exact input of pull request #4888. That input is `mando==0.8.2` at line 179 (R11).
- **Risk**: The test depends on the pin line format. Mitigation: `uv export` writes `mando==<version>` lines (R09, R48).
- **Human decision required**: No.

### D-4 Add the changelog fragment

- **Decision**: Add `changelog.d/issue-4902-mando-radon-pin.md` with one `Fixed` bullet.
- **Alternatives considered**:
  - Add no fragment, following README rule 4 (R25). Rejected, because the constitution says each change adds one unique fragment (R28), and the constitution governs when two rules conflict (R29).
  - Use a date-named fragment. Rejected, because the README names the issue form when no pull request exists (R24).
- **Rationale**: The change alters Dependabot behavior that contributors see.
- **Risk**: A reviewer may read README rule 4 as the governing rule. Mitigation: analysis A-5 records the conflict for the owner.
- **Human decision required**: No.

### D-5 Ship this record in the same pull request as the fix

- **Decision**: Add the record under the route leaf in the same pull request.
- **Alternatives considered**:
  - Open a separate documentation pull request. Rejected, because AGENTS asks for one change for each pull request, and the specification rule applies to three or more files (R47). Two pull requests add review work.
  - Keep the record out of the repository. Rejected, because reviewers then lack the decision trail for the policy change.
- **Rationale**: The change touches four paths. The specification rule applies (R47).
- **Risk**: The record adds Markdown files that STE must score. Mitigation: task T007 runs `ste-linter`.
- **Human decision required**: No.

### D-6 Close pull request #4888 after the ignore rule reaches main, with a preservation proof

- **Decision**: After the merge, close pull request #4888 with a closing comment that names the surviving branch and commit.
- **Alternatives considered**:
  - Close the pull request now. Rejected, because Dependabot might propose the update again before the rule exists (U-3).
  - Leave the pull request open. Rejected, because the open pull request keeps a failing check on the repository.
  - Close the pull request without a proof. Rejected, because AGENTS requires a preservation proof for an unmerged close (R49).
- **Rationale**: The branch `dependabot/pip/mando-0.8.2` at commit `e86098cd` survives the close (R08). That branch and commit form the proof.
- **Risk**: Deleting the branch early removes the reopen path. Mitigation: task T-MERGE keeps the branch until the comment posts.
- **Human decision required**: No.
