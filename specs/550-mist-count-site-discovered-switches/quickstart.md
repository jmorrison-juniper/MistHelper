# Phase 1 Quickstart: countSiteDiscoveredSwitches

**Spec**: [spec.md](./spec.md)
**Plan**: [plan.md](./plan.md)
**Date**: 2026-06-29

This quickstart shows a developer how to run, exercise, and validate the new menu item
on a Windows 11 dev box. Container parity is identical (paths normalize via
`pathlib.Path` and `os.path.join`).

## Prerequisites

- Windows 11 with PowerShell 7+ (or any shell on Linux container).
- Python 3.13 or newer on PATH.
- Repository cloned at the worktree root referenced in `plan.md`.
- Working `.venv` activated:

  ```powershell
  .venv\Scripts\Activate.ps1
  ```

- `mistapi` 0.59+ installed:

  ```powershell
  python -m pip install --upgrade mistapi python-dotenv
  ```

## Required `.env` variables

Create or update `.env` in the repository root (git-ignored). Never commit this file.

```ini
MIST_HOST=api.mist.com
MIST_API_TOKEN=<your-mist-api-token>
MIST_SITE_ID=<your-default-site-uuid>             # optional default for site_id prompt
MIST_DISCOVERED_SWITCHES_END=                     # optional override for the `end` query parameter
```

Loading is handled by the existing `python-dotenv` bootstrap in `MistHelper.py`. The
API token is consumed by `mistapi.APISession` and is never written to logs or stdout.

## Expected output filenames

Files land under `data/` (the directory is enforced at runtime; create it with
`chmod -R 777 data/` on Linux first to satisfy the non-root container user).

- Summary CSV: `data/site_<first-8-of-site-uuid>_discovered_switches_count_summary.csv`
- Groups CSV: `data/site_<first-8-of-site-uuid>_discovered_switches_count_groups.csv`
- SQLite: `data/mist_data.db`, tables `site_discovered_switches_count_summary` and
  `site_discovered_switches_count_groups`

## Skeleton of the new method

The full implementation is generated by `/speckit.implement`; this skeleton documents
the expected shape so that inline comment and action logging coverage can be reviewed
before the code is written. Every executable line carries a `#` comment (Constitution
VI), and every meaningful action is bracketed by `logging.info()` / `logging.debug()`
calls (Constitution VII).

```python
class DiscoveredSwitchesStatsUtils:                                                 # new class for the Sites Stats - Discovered Switches tag cluster

    def __init__(self, apisession):                                                 # capture the active mistapi APISession
        self.apisession = apisession                                                # store for use by every public method

    def export_site_discovered_switches_count(                                      # menu 91 entrypoint
        self, site_id=None, distinct="", duration="1d", limit=100,                  # all parameters honor caller overrides
    ):
        logging.info("Prompting for site_id for discovered switches count")         # before-prompt action log
        site_id = site_id or safe_input(                                            # honor caller override else prompt user
            "Site ID (UUID): ",                                                     # human-readable prompt text
            context="site_discovered_switches_count:site_id",                       # SSH/container EOF context tag
            default=os.environ.get("MIST_SITE_ID", ""),                             # fall back to .env default
        )
        if not is_valid_uuid(site_id):                                              # validate before any API call
            logging.warning("Invalid site_id %s -- aborting menu 91", site_id)      # log validation failure (no traceback)
            return                                                                  # early return per safety-first principle

        distinct = distinct or safe_input(                                          # group-by attribute (blank = ungrouped)
            "Group by distinct attribute (vendor/model/version/...), blank for no grouping: ",
            context="site_discovered_switches_count:distinct",                      # EOF context tag
            default="",                                                             # default is no grouping
        )
        duration = duration or safe_input(                                          # time-window duration
            "Duration (e.g. 1d, 7d, 2w) [1d]: ",                                    # default in prompt for visibility
            context="site_discovered_switches_count:duration",                      # EOF context tag
            default="1d",                                                           # API default mirrored
        )
        end_override = os.environ.get("MIST_DISCOVERED_SWITCHES_END") or None       # optional .env override for end

        logging.info(                                                               # before-API-call action log
            "Counting discovered switches at site %s (distinct=%s, duration=%s, limit=%s)",
            site_id, distinct or "<none>", duration, limit,
        )
        response = mistapi.api.v1.sites.stats.discovered_switches.count.countSiteDiscoveredSwitches(  # actual SDK call
            self.apisession, site_id,                                               # required positional args
            distinct=distinct or None, duration=duration,                           # omit distinct when blank
            limit=limit, end=end_override,                                          # forward optional params verbatim
        )
        body = response.data or {}                                                  # normalize None to empty dict
        logging.debug(                                                              # after-API-call summary log
            "Discovered switches count: total=%s groups=%s",
            body.get("total"), len(body.get("results") or []),
        )

        summary_row = self._flatten_count_summary(site_id, duration, body)          # build one summary dict
        logging.debug("Flattened 1 summary row")                                    # after-flatten count log
        group_rows = self._flatten_count_groups(site_id, body)                      # build N group dicts
        logging.debug("Flattened %d group rows", len(group_rows))                   # after-flatten count log

        logging.info("Writing discovered switches count summary via DataExporter")  # before-export action log
        DataExporter.write_with_format_selection(                                   # multi-backend summary write
            [summary_row],                                                          # list-of-rows interface
            filename=f"site_{site_id[:8]}_discovered_switches_count_summary",       # human-friendly stem
            api_function_name="countSiteDiscoveredSwitches",                        # PK strategy lookup key
        )
        logging.info("Writing discovered switches count groups via DataExporter")   # before-export action log
        DataExporter.write_with_format_selection(                                   # multi-backend groups write
            group_rows,                                                             # may be empty list when API returns nothing
            filename=f"site_{site_id[:8]}_discovered_switches_count_groups",        # human-friendly stem
            api_function_name="countSiteDiscoveredSwitchesGroups",                  # MistHelper-internal sub-table key
        )
```

Helpers `_flatten_count_summary` and `_flatten_count_groups` follow the same comment-
and log-density rules, stay under 25 lines, and live on the same
`DiscoveredSwitchesStatsUtils` class -- no standalone wrapper functions.
