# Phase 1 Quickstart: getOrgSsrUpgrade

**Spec**: [spec.md](./spec.md)
**Plan**: [plan.md](./plan.md)
**Date**: 2026-06-30

This quickstart shows a developer how to run, exercise, and validate the new
menu item on a Windows 11 dev box. Container parity is identical (path
separators normalize via `pathlib.Path` and `os.path.join`).

## Prerequisites

- Windows 11 with PowerShell 7+ (any shell works inside the Linux container).
- Python 3.13 or newer on PATH.
- Repository cloned at the worktree root referenced in `plan.md`.
- Working `.venv` activated:

  ```powershell
  .venv\Scripts\Activate.ps1
  ```

- `mistapi` 0.59+ installed:

  ```powershell
  python -m pip install --upgrade mistapi python-dotenv
  ```

## Required `.env` variables

Create or update `.env` in the repository root (git-ignored -- never commit).

```ini
MIST_HOST=api.mist.com
MIST_API_TOKEN=<your-mist-api-token>
MIST_ORG_ID=<your-default-org-uuid>            # optional default for prompt 1
MIST_SSR_UPGRADE_ID=<a-known-upgrade-uuid>     # optional default for prompt 2
```

Loading is handled by the existing `python-dotenv` bootstrap in
`MistHelper.py`. The API token is consumed by `mistapi.APISession` and is
never written to logs or stdout. The two ID variables are pure convenience
defaults for repeated polling and the `--test` sweep.

## Expected output filenames

Files land under `data/` (the directory is enforced at runtime; on Linux
create it and set writable perms first so the non-root container user can
write: `chmod -R 777 data/`).

- Summary CSV: `data/org_<first-8-of-org-uuid>_ssr_upgrade_<first-8-of-upgrade-uuid>_summary.csv`
- Targets CSV: `data/org_<first-8-of-org-uuid>_ssr_upgrade_<first-8-of-upgrade-uuid>_targets.csv`
- SQLite: `data/mist_data.db`, tables `org_ssr_upgrade_summary` and
  `org_ssr_upgrade_targets` (schema in `data-model.md`).

## Skeleton of the new method

The full implementation is generated by `/speckit.implement`; this skeleton
documents the expected shape so that inline comment and action logging
coverage can be reviewed *before* the code is written. Every executable line
carries a same-line `#` comment (Constitution VI); every meaningful action is
bracketed by `logging.info()` before and `logging.debug()` after
(Constitution VII).

```python
class FirmwareManager:                                                              # existing class -- no wrapper introduced

    def export_org_ssr_upgrade_status(self, org_id=None, upgrade_id=None):          # menu 96 entrypoint
        logging.info("Prompting for org_id for SSR upgrade status")                 # before-prompt action log
        org_id = org_id or safe_input(                                              # honor caller override else prompt user
            "Org ID (UUID) [Enter for .env default]: ",                             # human-readable prompt text
            context="org_ssr_upgrade_status:org_id",                                # SSH/container EOF context tag
            default=os.environ.get("MIST_ORG_ID", ""),                              # fall back to .env default
        )
        if not is_valid_uuid(org_id):                                               # validate before any network I/O
            logging.warning("Invalid org_id %s -- aborting menu 96", org_id)        # log validation failure (no traceback)
            return                                                                  # early return per safety-first principle

        logging.info("Prompting for upgrade_id for SSR upgrade status")             # before-prompt action log
        upgrade_id = upgrade_id or safe_input(                                      # honor caller override else prompt user
            "SSR upgrade ID (UUID): ",                                              # human-readable prompt text
            context="org_ssr_upgrade_status:upgrade_id",                            # EOF context tag
            default=os.environ.get("MIST_SSR_UPGRADE_ID", ""),                      # fall back to .env default
        )
        if not is_valid_uuid(upgrade_id):                                           # validate before any network I/O
            logging.warning("Invalid upgrade_id %s -- aborting menu 96", upgrade_id)  # log validation failure
            return                                                                  # early return per safety-first principle

        logging.info("Fetching SSR upgrade status org=%s upgrade=%s", org_id, upgrade_id)  # before-API-call action log
        response = mistapi.api.v1.orgs.ssr.upgrade.cancel.getOrgSsrUpgrade(         # SDK call (GET despite /cancel suffix)
            self.apisession, org_id, upgrade_id,                                    # required path params
        )
        body = response.data or {}                                                  # normalize None to empty dict
        targets = body.get("targets") or {}                                         # defensive default for missing key
        logging.debug(                                                              # after-API-call summary log
            "SSR upgrade status=%s targets_success=%d targets_failed=%d targets_queued=%d targets_upgrading=%d",
            body.get("status"),
            len(targets.get("success") or []),
            len(targets.get("failed") or []),
            len(targets.get("queued") or []),
            len(targets.get("upgrading") or []),
        )

        logging.info("Flattening SSR upgrade summary payload")                      # before-flatten action log
        summary_row = self._flatten_ssr_upgrade_summary(org_id, body)               # build one summary dict
        logging.debug("Flattened 1 summary row")                                    # after-flatten count log

        logging.info("Flattening SSR upgrade targets (4 buckets)")                  # before-flatten action log
        target_rows = self._flatten_ssr_upgrade_targets(org_id, body)               # build zero-or-more target dicts
        logging.debug("Flattened %d target rows", len(target_rows))                 # after-flatten count log

        logging.info("Writing SSR upgrade summary via DataExporter")                # before-export action log
        DataExporter.write_with_format_selection(                                   # multi-backend write for summary
            [summary_row],                                                          # list-of-rows interface
            filename=f"org_{org_id[:8]}_ssr_upgrade_{upgrade_id[:8]}_summary",      # human-friendly stem
            api_function_name="getOrgSsrUpgrade",                                   # PK strategy lookup key (natural_pk on id)
        )

        logging.info("Writing SSR upgrade targets via DataExporter")                # before-export action log
        DataExporter.write_with_format_selection(                                   # multi-backend write for targets
            target_rows,                                                            # may be empty list when all buckets empty
            filename=f"org_{org_id[:8]}_ssr_upgrade_{upgrade_id[:8]}_targets",      # human-friendly stem
            api_function_name="getOrgSsrUpgradeTargets",                            # PK strategy lookup key (composite_pk)
        )
```

Helpers `_flatten_ssr_upgrade_summary` and `_flatten_ssr_upgrade_targets`
follow the same comment- and log-density rules, stay under 15 lines each,
and live on the same `FirmwareManager` class -- no standalone wrapper
functions.

## Quality gates (all must pass before commit)

Run these from the repository root with the venv active:

```powershell
python -m py_compile MistHelper.py        # 1. Syntax check (zero output = pass)
python -m ruff check MistHelper.py        # 2. Lint (zero violations = pass)
python -m black --check MistHelper.py     # 3. Format (zero diffs = pass; rerun without --check to auto-fix)
python MistHelper.py --test               # 4. Functional smoke test (menu 96 included)
```

The `--test` sweep automatically skips heavy / destructive operations (14,
18, 63-65, 90-100). Menu 96 sits inside the standard sweep range at the top
of the Viewers cluster, so a green run confirms the new item works end-to-end
against the org and upgrade configured in `.env`. If `MIST_SSR_UPGRADE_ID` is
unset the sweep should log a WARNING and return cleanly (validation catches
the empty string before the SDK call).
