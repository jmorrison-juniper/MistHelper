# Phase 1 Quickstart: countOrgTickets

**Spec**: [spec.md](./spec.md)
**Plan**: [plan.md](./plan.md)
**Date**: 2026-06-29

This quickstart shows a developer how to run, exercise, and validate the new menu
item on a Windows 11 dev box. Container parity is identical (paths normalize via
`pathlib.Path` and `os.path.join`).

## Prerequisites

- Windows 11 with PowerShell 7+ (or any shell on the Linux container).
- Python 3.13 or newer on PATH.
- Repository cloned at the worktree root referenced in `plan.md`.
- Working `.venv` activated:

  ```powershell
  .venv\Scripts\Activate.ps1
  ```

- `mistapi` 0.59+ installed:

  ```powershell
  python -m pip install --upgrade mistapi python-dotenv
  ```

## Required `.env` variables

Create or update `.env` in the repository root (git-ignored). Never commit this
file.

```ini
MIST_HOST=api.mist.com
MIST_API_TOKEN=<your-mist-api-token>
MIST_ORG_ID=<your-default-org-uuid>   # optional default for the org_id prompt
```

Loading is handled by the existing `python-dotenv` bootstrap in `MistHelper.py`.
The API token is consumed by `mistapi.APISession` and is never written to logs or
stdout.

## Expected output filenames

Files land under `data/` (the directory is enforced at runtime; create it with
`chmod -R 777 data/` on Linux first to satisfy the non-root container user).

- Summary CSV: `data/org_<first-8-of-org-uuid>_tickets_count_summary.csv`
- Results CSV: `data/org_<first-8-of-org-uuid>_tickets_count_results.csv`
- SQLite: `data/mist_data.db`, tables `org_tickets_count_summary` and
  `org_tickets_count_results`

## Skeleton of the new method

The full implementation is generated by `/speckit.implement`; this skeleton
documents the expected shape so that inline comment and action logging coverage can
be reviewed before code is written. Every executable line carries a `#` comment
(Constitution VI), and every meaningful action is bracketed by `logging.info()` /
`logging.debug()` calls (Constitution VII).

```python
class TicketExportUtils:                                                             # new class -- no existing class owns Orgs Tickets

    def export_org_tickets_count(self, org_id=None, distinct=None, limit=None):     # menu 58 entrypoint
        logging.info("Prompting for org_id for tickets count menu item")            # before-prompt action log
        org_id = org_id or safe_input(                                              # honor caller override else prompt user
            "Org ID (UUID): ",                                                      # human-readable prompt text
            context="org_tickets_count:org_id",                                     # SSH/container EOF context tag
            default=os.environ.get("MIST_ORG_ID", ""),                              # fall back to .env default
        )
        if not is_valid_uuid(org_id):                                               # validate before any API call
            logging.warning("Invalid org_id %s -- aborting menu 58", org_id)        # log validation failure (no traceback)
            return                                                                  # early return per safety-first principle

        logging.info("Prompting for distinct field")                                # before-prompt action log
        distinct_input = distinct if distinct is not None else safe_input(          # honor caller override else prompt user
            "Distinct field (e.g., status, type, created_by; blank for API default): ",  # human-readable prompt text
            context="org_tickets_count:distinct",                                   # EOF context tag
            default="",                                                             # blank means server-side default
        )
        distinct_value = distinct_input.strip() or None                             # normalize empty string to None for SDK
        distinct_key = distinct_value or "__server_default__"                       # sentinel for the PK so polls upsert cleanly

        logging.info("Prompting for limit")                                         # before-prompt action log
        limit_input = limit if limit is not None else safe_input(                   # honor caller override else prompt user
            "Limit (1-1000, default 100): ",                                        # human-readable prompt text
            context="org_tickets_count:limit",                                      # EOF context tag
            default="100",                                                          # API default is 100
        )
        try:                                                                        # guard int coercion -- bad input is recoverable
            limit_int = int(str(limit_input).strip() or "100")                      # coerce user value or fall back to 100
        except ValueError:                                                          # non-numeric input falls through
            logging.warning("Non-numeric limit %s -- using 100", limit_input)       # log and recover, do not crash
            limit_int = 100                                                         # safe default

        logging.info("Counting org tickets for org %s by %s",                       # before-API-call action log
                     org_id, distinct_key)
        response = mistapi.api.v1.orgs.tickets.countOrgTickets(                     # actual SDK call
            self.apisession, org_id,                                                # required positional args
            distinct=distinct_value, limit=limit_int,                               # optional query params
        )
        body = response.data or {}                                                  # normalize None to empty dict
        results = body.get("results", []) or []                                     # normalize None to empty list
        logging.debug("Tickets count: total=%s buckets=%s",                         # after-API-call summary log
                      body.get("total"), len(results))

        polled_at_utc = datetime.datetime.utcnow().isoformat(timespec="seconds")    # single timestamp for both rows
        logging.info("Flattening summary envelope")                                 # before-flatten action log
        summary_row = self._flatten_tickets_summary(                                # build one summary dict
            org_id, distinct_key, polled_at_utc, body, len(results),
        )
        logging.debug("Flattened 1 summary row")                                    # after-flatten count log

        logging.info("Flattening %d result buckets", len(results))                  # before-flatten action log
        result_rows = self._flatten_tickets_results(                                # build one row per bucket
            org_id, distinct_key, polled_at_utc, results,
        )
        logging.debug("Flattened %d result rows", len(result_rows))                 # after-flatten count log

        logging.info("Writing tickets count summary via DataExporter")              # before-export action log
        DataExporter.write_with_format_selection(                                   # multi-backend write -- summary
            [summary_row],                                                          # list-of-rows interface
            filename=f"org_{org_id[:8]}_tickets_count_summary",                     # human-friendly stem
            api_function_name="countOrgTickets",                                    # PK strategy lookup key (operationId)
        )

        logging.info("Writing tickets count results via DataExporter")              # before-export action log
        DataExporter.write_with_format_selection(                                   # multi-backend write -- results
            result_rows,                                                            # may be empty list when no buckets
            filename=f"org_{org_id[:8]}_tickets_count_results",                     # human-friendly stem
            api_function_name="countOrgTicketsResults",                             # MistHelper-internal sub-table key
        )
```

Helpers `_flatten_tickets_summary` and `_flatten_tickets_results` follow the same
comment- and log-density rules, stay under 25 lines each, and live on the same
`TicketExportUtils` class -- no standalone wrapper functions.
