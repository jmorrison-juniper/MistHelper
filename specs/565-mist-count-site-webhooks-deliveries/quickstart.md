# Phase 1 Quickstart: countSiteWebhooksDeliveries

**Spec**: [spec.md](./spec.md)
**Plan**: [plan.md](./plan.md)
**Date**: 2026-06-29

This quickstart shows a developer how to run, exercise, and validate the new menu item
on a Windows 11 dev box. Container parity is identical (paths normalize via
`pathlib.Path` and `os.path.join`).

## Prerequisites

- Windows 11 with PowerShell 7+ (or any shell on Linux container).
- Python 3.13 or newer on PATH.
- Repository cloned at the worktree root referenced in `plan.md`.
- Working `.venv` activated:

  ```powershell
  .venv\Scripts\Activate.ps1
  ```

- `mistapi` 0.59+ installed:

  ```powershell
  python -m pip install --upgrade mistapi python-dotenv
  ```

## Required `.env` variables

Create or update `.env` in the repository root (git-ignored). Never commit this file.

```ini
MIST_HOST=api.mist.com
MIST_API_TOKEN=<your-mist-api-token>
MIST_SITE_ID=<your-default-site-uuid>          # optional default for site_id prompt
MIST_WEBHOOK_ID=<your-default-webhook-uuid>    # optional default for webhook_id prompt
MIST_WEBHOOK_COUNT_START=                      # optional epoch override (advanced)
MIST_WEBHOOK_COUNT_END=                        # optional epoch override (advanced)
```

Loading is handled by the existing `python-dotenv` bootstrap in `MistHelper.py`. The API
token is consumed by `mistapi.APISession` and is never written to logs or stdout.

## Expected output filenames

Files land under `data/` (the directory is enforced at runtime; create it with
`chmod -R 777 data/` on Linux first to satisfy the non-root container user).

- Summary CSV:
  `data/site_<first-8-of-site-uuid>_webhook_<first-8-of-webhook-uuid>_count_summary.csv`
- Buckets CSV:
  `data/site_<first-8-of-site-uuid>_webhook_<first-8-of-webhook-uuid>_count_buckets.csv`
- SQLite: `data/mist_data.db`, tables `site_webhook_deliveries_count_summary` and
  `site_webhook_deliveries_count_buckets`.

## Skeleton of the new method

The full implementation is generated by `/speckit.implement`; this skeleton documents
the expected shape so inline-comment and action-logging coverage can be reviewed before
the code is written. Every executable line carries a `#` comment (Constitution VI), and
every meaningful action is bracketed by `logging.info()` / `logging.debug()` calls
(Constitution VII).

```python
class WebhookExportUtils:                                                           # existing class, no new wrapper

    def export_site_webhook_deliveries_count(self, site_id=None, webhook_id=None,   # menu 86 entrypoint
                                              distinct=None, filters=None):         # filters dict bundles optional knobs
        logging.info("Prompting for site_id for webhook count menu item")           # before-prompt action log
        site_id = site_id or safe_input(                                            # honor caller override else prompt
            "Site ID (UUID): ",                                                     # human-readable prompt text
            context="site_webhook_count:site_id",                                   # SSH/container EOF context tag
            default=os.environ.get("MIST_SITE_ID", ""),                             # fall back to .env default
        )
        if not is_valid_uuid(site_id):                                              # validate before any API call
            logging.warning("Invalid site_id %s -- aborting menu 86", site_id)      # log validation failure (no traceback)
            return                                                                  # early return per safety-first

        logging.info("Prompting for webhook_id for webhook count menu item")        # before-prompt action log
        webhook_id = webhook_id or safe_input(                                      # honor caller override else prompt
            "Webhook ID (UUID): ",                                                  # human-readable prompt text
            context="site_webhook_count:webhook_id",                                # EOF context tag
            default=os.environ.get("MIST_WEBHOOK_ID", ""),                          # fall back to .env default
        )
        if not is_valid_uuid(webhook_id):                                           # validate before any API call
            logging.warning("Invalid webhook_id %s -- aborting", webhook_id)        # log validation failure
            return                                                                  # early return

        logging.info("Collecting optional filters for webhook count")               # before-prompt action log
        filters = filters or self._prompt_webhook_count_filters()                   # private helper bundles optional prompts

        logging.info(                                                               # before-API-call action log
            "Counting webhook deliveries for site %s webhook %s distinct=%s",
            site_id[:8], webhook_id[:8], filters.get("distinct") or "_overall",
        )
        response = mistapi.api.v1.sites.webhooks.events.count.countSiteWebhooksDeliveries(  # SDK call
            self.apisession, site_id, webhook_id, **filters,                        # unpack optional kwargs
        )
        body = response.data or {}                                                  # normalize None to empty dict
        logging.debug(                                                              # after-API-call summary log
            "Webhook count: total=%s buckets=%s window=%s..%s",
            body.get("total"), len(body.get("results") or []),
            body.get("start"), body.get("end"),
        )

        logging.info("Flattening summary envelope for webhook %s", webhook_id[:8])  # before-flatten action log
        summary_row = self._flatten_webhook_count_summary(                          # build one summary dict
            site_id, webhook_id, filters, body,
        )
        logging.debug("Flattened 1 summary row")                                    # after-flatten count log
        logging.info("Writing webhook count summary via DataExporter")              # before-export action log
        DataExporter.write_with_format_selection(                                   # multi-backend write
            [summary_row],                                                          # list-of-rows interface
            filename=f"site_{site_id[:8]}_webhook_{webhook_id[:8]}_count_summary",  # human-friendly stem
            api_function_name="countSiteWebhooksDeliveries",                        # PK strategy lookup key
        )

        logging.info("Flattening %d bucket rows", len(body.get("results") or []))   # before-flatten action log
        bucket_rows = self._flatten_webhook_count_buckets(                          # one row per bucket
            site_id, webhook_id, filters, body,
        )
        logging.debug("Flattened %d bucket rows", len(bucket_rows))                 # after-flatten count log
        logging.info("Writing webhook count buckets via DataExporter")              # before-export action log
        DataExporter.write_with_format_selection(                                   # second multi-backend write
            bucket_rows,                                                            # may be empty list
            filename=f"site_{site_id[:8]}_webhook_{webhook_id[:8]}_count_buckets",  # human-friendly stem
            api_function_name="countSiteWebhooksDeliveriesBuckets",                 # MistHelper-internal sub-table key
        )
```

Helpers `_prompt_webhook_count_filters`, `_flatten_webhook_count_summary`, and
`_flatten_webhook_count_buckets` follow the same comment- and log-density rules, stay
under 25 lines, and live on the same `WebhookExportUtils` class -- no standalone
wrapper functions.

```powershell

python -m ruff check MistHelper.py        # 2. Lint (zero violations = pass)
python -m black --check MistHelper.py     # 3. Format (zero diffs = pass; rerun without --check to auto-fix)
python MistHelper.py --test               # 4. Functional smoke test (menu 86 included)
```

The `--test` sweep automatically skips heavy/destructive operations (14, 18, 63-65,
90-100). Menu 86 sits inside the default sweep range, so a green run confirms the new
item works end to end against the site and webhook configured in `.env`.
