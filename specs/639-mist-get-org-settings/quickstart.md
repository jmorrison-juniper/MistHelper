# Phase 1 Quickstart: getOrgSettings

**Spec**: [spec.md](./spec.md)
**Plan**: [plan.md](./plan.md)
**Date**: 2026-06-30

This quickstart shows a developer how to run, exercise, and validate the new
menu item on a Windows 11 dev box. Container parity is identical (paths
normalize via `pathlib.Path` and `os.path.join`).

## Prerequisites

- Windows 11 with PowerShell 7+ (or any shell on Linux container).
- Python 3.13 or newer on PATH.
- Repository cloned at the worktree root referenced in `plan.md`.
- Working `.venv` activated:

  ```powershell
  .venv\Scripts\Activate.ps1
  ```

- `mistapi` 0.59+ installed:

  ```powershell
  python -m pip install --upgrade mistapi python-dotenv
  ```

## Required `.env` variables

Create or update `.env` in the repository root (git-ignored). Never commit
this file.

```ini
MIST_HOST=api.mist.com
MIST_API_TOKEN=<your-mist-api-token>
MIST_ORG_ID=<your-default-org-uuid>   # optional default for the org_id prompt
```

Loading is handled by the existing `python-dotenv` bootstrap in
`MistHelper.py`. The API token is consumed by `mistapi.APISession` and is
never written to logs or stdout.

## Expected output filenames

Files land under `data/` (the directory is enforced at runtime; create it
with `chmod -R 777 data/` on Linux first to satisfy the non-root container
user).

- Parent CSV: `data/org_<first-8-of-org-uuid>_settings.csv`
- Rule side CSV 1: `data/org_<first-8-of-org-uuid>_settings_auto_device_naming_rules.csv`
- Rule side CSV 2: `data/org_<first-8-of-org-uuid>_settings_auto_deviceprofile_assignment_rules.csv`
- SQLite: `data/mist_data.db`, tables `org_settings`,
  `org_settings_auto_device_naming_rules`,
  `org_settings_auto_deviceprofile_assignment_rules`

## Skeleton of the new method

The full implementation is generated by `/speckit.implement`; this skeleton
documents the expected shape so that inline-comment and action-logging
coverage can be reviewed before the code is written. Every executable line
carries a `#` comment (Constitution VI), and every meaningful action is
bracketed by `logging.info()` / `logging.debug()` calls (Constitution VII).

```python
class OrgConfigExportUtils:                                                         # existing class, no new wrapper

    def export_org_settings(self, org_id=None):                                     # menu 58 entrypoint
        logging.info("Prompting for org_id for org settings menu item")             # before-prompt action log
        org_id = org_id or safe_input(                                              # honor caller override else prompt user
            "Org ID (UUID): ",                                                      # human-readable prompt text
            context="org_settings:org_id",                                          # SSH/container EOF context tag
            default=os.environ.get("MIST_ORG_ID", ""),                              # fall back to .env default
        )
        if not is_valid_uuid(org_id):                                               # validate before any API call
            logging.warning("Invalid org_id %s -- aborting menu 58", org_id)        # log validation failure (no traceback)
            return                                                                  # early return per safety-first principle

        logging.info("Fetching org settings for org %s", org_id)                    # before-API-call action log
        response = mistapi.api.v1.orgs.setting.getOrgSettings(                      # actual SDK call
            self.apisession, org_id,                                                # required path parameter only
        )
        body = response.data or {}                                                  # normalize None to empty dict
        naming_rules = (body.get("auto_device_naming") or {}).get("rules") or []    # extract nested array 1
        devprof_rules = (                                                           # extract nested array 2
            body.get("auto_deviceprofile_assignment") or {}
        ).get("rules") or []
        logging.debug(                                                              # after-API-call summary log
            "Org settings: keys=%d naming_rules=%d deviceprofile_rules=%d",
            len(body), len(naming_rules), len(devprof_rules),
        )

        logging.info("Flattening summary payload for org %s", org_id)               # before-flatten action log
        summary_row = self._flatten_org_settings_summary(org_id, body)              # build one wide parent row
        logging.debug("Flattened 1 summary row")                                    # after-flatten count log

        logging.info("Flattening %d auto_device_naming rule rows", len(naming_rules))    # before-flatten action log
        naming_rule_rows = self._flatten_naming_rules(org_id, naming_rules)         # side-table 1 rows
        logging.debug("Flattened %d auto_device_naming rule rows", len(naming_rule_rows)) # after-flatten count log

        logging.info("Flattening %d auto_deviceprofile_assignment rule rows", len(devprof_rules)) # before-flatten
        devprof_rule_rows = self._flatten_devprof_rules(org_id, devprof_rules)      # side-table 2 rows
        logging.debug("Flattened %d auto_deviceprofile_assignment rule rows", len(devprof_rule_rows)) # after-flatten

        logging.info("Writing org settings summary via DataExporter")               # before-export action log
        DataExporter.write_with_format_selection(                                   # multi-backend write for parent
            [summary_row], filename=f"org_{org_id[:8]}_settings",                   # human-friendly stem
            api_function_name="getOrgSettings",                                     # PK strategy lookup key
        )

        logging.info("Writing org settings auto_device_naming rules via DataExporter")  # before-export action log
        DataExporter.write_with_format_selection(                                   # multi-backend write for side table 1
            naming_rule_rows,                                                       # may be empty list
            filename=f"org_{org_id[:8]}_settings_auto_device_naming_rules",         # human-friendly stem
            api_function_name="getOrgSettingsAutoDeviceNamingRules",                # MistHelper-internal sub-table key
        )

        logging.info("Writing org settings auto_deviceprofile_assignment rules via DataExporter") # before-export
        DataExporter.write_with_format_selection(                                   # multi-backend write for side table 2
            devprof_rule_rows,                                                      # may be empty list
            filename=f"org_{org_id[:8]}_settings_auto_deviceprofile_assignment_rules", # human-friendly stem
            api_function_name="getOrgSettingsAutoDeviceprofileAssignmentRules",     # MistHelper-internal sub-table key
        )
```

Helpers `_flatten_org_settings_summary`, `_flatten_naming_rules`, and
`_flatten_devprof_rules` follow the same comment- and log-density rules, stay
under 25 lines each, and live on the same `OrgConfigExportUtils` class -- no
standalone wrapper functions. `_flatten_org_settings_summary` uses
`json.dumps(..., sort_keys=True)` to serialize each retained nested object
into its `*_json` column so the SQLite row stays queryable while preserving
full fidelity.

## Quality gates (all must pass before commit)

Run these from the repository root with the venv active:

```powershell
python -m py_compile MistHelper.py        # 1. Syntax check (zero output = pass)
python -m ruff check MistHelper.py        # 2. Lint (zero violations = pass)
python -m black --check MistHelper.py     # 3. Format (zero diffs = pass; rerun without --check to auto-fix)
python MistHelper.py --test               # 4. Functional smoke test (menu 58 included)
```

The `--test` sweep automatically skips heavy/destructive operations (14, 18,
63-65, 90-100). Menu 58 sits inside the standard sweep range, so a green run
confirms the new item works end to end against the org configured in `.env`.
