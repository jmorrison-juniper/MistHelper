# Phase 1 Data Model: getOrg128TRegistrationCommands

**Spec**: [spec.md](./spec.md) | **Plan**: [plan.md](./plan.md) |
**Contract**: [contracts/get_org128_t_registration_commands.md](./contracts/get_org128_t_registration_commands.md)

## Entity: Org128TRegistrationCommand

The endpoint returns a single JSON object per request, not an array. The
three fields are the bundle of credentials and shell commands required
to onboard a 128T / SSR router into the Mist organization. MistHelper
treats the bundle as one row keyed by `(org_id, registration_code)`,
with two additional columns appended at flatten time so the row carries
enough context for offline analysis without a JOIN.

### Fields

| Column                | Source                                  | Type    | Nullable | Description |
|-----------------------|-----------------------------------------|---------|----------|-------------|
| `org_id`              | injected from the prompted path param   | TEXT    | NO       | Mist organization UUID (PK part 1, FK to `org_sites.org_id`). |
| `registration_code`   | response field `registration_code`      | TEXT    | NO       | Server-minted, time-limited registration token (PK part 2). |
| `conductor_cmd`       | response field `conductor_cmd`          | TEXT    | YES      | Full conductor-side shell command. Sensitive -- never echoed to stdout. |
| `router_shell_cmd`    | response field `router_shell_cmd`       | TEXT    | YES      | Full router-side shell command. Sensitive -- never echoed to stdout. |
| `requested_ttl`       | echoed from the optional `ttl` query    | INTEGER | YES      | TTL (seconds) the user supplied for this call. NULL when omitted. |
| `requested_at_utc`    | MistHelper-side `datetime.utcnow()`     | TEXT    | NO       | ISO-8601 UTC timestamp when the call was made. Used for audit only. |

**Primary key**: composite `(org_id, registration_code)`.
**Foreign key (logical)**: `org_id` references `org_sites.org_id` populated by
existing menu item 1 (List Org Sites).
**Indexes**: `org_id` (single-column) for fast per-org filtering;
`registration_code` (single-column) for direct lookup when an operator
pastes a code back into MistHelper for diagnostics.

### State Transitions

N/A -- read-only endpoint. Each call produces a fresh, time-limited
bundle. Re-running the menu item upserts on the composite key:

- If Mist returns a new `registration_code`, a new row is inserted.
- If Mist returns the same `registration_code` for the same `org_id`
  (unlikely but possible inside a TTL window), `INSERT OR REPLACE`
  refreshes the row in place.

No status column, no lifecycle workflow. Historical retention, if ever
required, is achieved by a separate append-only history table layered on
top of this base table.

## SQLite DDL

```sql
-- Generated by DataExporter on first run from the registered
-- ENDPOINT_PRIMARY_KEY_STRATEGIES entry. Shown here so the data model
-- is reviewable without bootstrapping the runtime.
CREATE TABLE IF NOT EXISTS org_128t_registration_commands (
    org_id            TEXT    NOT NULL,                       -- Mist org UUID, PK part 1
    registration_code TEXT    NOT NULL,                       -- server-minted token, PK part 2
    conductor_cmd     TEXT,                                   -- conductor shell command (sensitive)
    router_shell_cmd  TEXT,                                   -- router shell command (sensitive)
    requested_ttl     INTEGER,                                -- echo of the optional ttl query param
    requested_at_utc  TEXT    NOT NULL,                       -- ISO-8601 UTC capture timestamp
    PRIMARY KEY (org_id, registration_code)                   -- composite natural key
);

CREATE INDEX IF NOT EXISTS idx_org_128t_register_cmd_org
    ON org_128t_registration_commands (org_id);               -- per-org filter accelerator

CREATE INDEX IF NOT EXISTS idx_org_128t_register_cmd_code
    ON org_128t_registration_commands (registration_code);    -- direct token lookup accelerator
```

## Multi-Backend Persistence Notes

- **CSV** (default backend): one file `data/org_128t_registration_commands.csv`
  written by `DataExporter`. Header row matches the column list above
  in declaration order. Each invocation appends a row if the
  `(org_id, registration_code)` pair is new; CSV does not enforce the
  PK, so duplicate suppression for the CSV backend relies on the
  pre-write deduplication performed by `DataExporter` against the
  in-memory frame.
- **SQLite** (`data/mist_data.db`): table created on first run from the
  registered PK strategy; upsert semantics via `INSERT OR REPLACE` keyed
  by the composite PK.
- **ArangoDB + Redis** (polyglot backend): vertex collection
  `org_128t_registration_commands` keyed by
  `"{org_id}:{registration_code}"`; graph edge from the existing
  `orgs/{org_id}` vertex (created by spec 188's graph-edge definitions)
  to this vertex with edge type `has_128t_registration_command`; Redis
  cache key `mist:org:{org_id}:128t_register_cmd:{registration_code}`
  with TTL set to `requested_ttl` when present, otherwise 3600 seconds.
