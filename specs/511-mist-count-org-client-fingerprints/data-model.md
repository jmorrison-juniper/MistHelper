# Phase 1 Data Model: countOrgClientFingerprints

**Spec**: [spec.md](./spec.md) | **Plan**: [plan.md](./plan.md) | **Research**: [research.md](./research.md)
**Endpoint**: `GET /api/v1/sites/{site_id}/insights/fingerprints/count`

## Entities

### Entity 1: `FingerprintCountSummary`

Represents one aggregate query result: the total count of client
fingerprints at a given site, grouped by the chosen `distinct` field,
over a bounded time window. One row per `(site_id, distinct, start, end)`
combination.

| Field | Type | Required | PK | FK | Description |
|-------|------|----------|----|----|-------------|
| `site_id` | TEXT (UUID) | Yes | Yes | -> `sites.id` | Site under which fingerprints were observed. Supplied by the user, not by the API response. |
| `distinct` | TEXT | Yes | Yes |  | Field used to bucket counts (for example `family`, `model`, `os`, `manufacturer`). API may return empty string when grouping is server-default. |
| `start` | INTEGER | Yes | Yes |  | Window start as epoch seconds. Echoed by the API in the response. |
| `end` | INTEGER | Yes | Yes |  | Window end as epoch seconds. Echoed by the API in the response. |
| `limit` | INTEGER | Yes |  |  | Max number of buckets requested. Echoed by the API. |
| `total` | INTEGER | Yes |  |  | Total bucket count returned (may be <= `limit`). |
| `retrieved_at` | TEXT (ISO 8601) | Yes |  |  | UTC timestamp set by MistHelper at write time. Not part of PK. |

### Entity 2: `FingerprintCountBucket`

Represents one bucket within a `FingerprintCountSummary` -- a `(distinct
value, count)` pair returned in the `results` array. Zero or more rows
per parent summary, capped by `limit`.

| Field | Type | Required | PK | FK | Description |
|-------|------|----------|----|----|-------------|
| `site_id` | TEXT (UUID) | Yes | Yes | -> `sites.id` | Inherited from parent summary. |
| `distinct` | TEXT | Yes | Yes |  | Inherited from parent summary. |
| `start` | INTEGER | Yes | Yes |  | Inherited from parent summary. |
| `end` | INTEGER | Yes | Yes |  | Inherited from parent summary. |
| `bucket_value` | TEXT | Yes | Yes |  | The distinct-field value for this bucket. Comes from the `additionalProperties` string on each `results[]` item (for example "Apple", "iPhone15,2"). Empty string when the API returns no key (rare edge case). |
| `count` | INTEGER | Yes |  |  | Number of client fingerprints in this bucket. Required by the OpenAPI schema. |
| `retrieved_at` | TEXT (ISO 8601) | Yes |  |  | UTC timestamp set by MistHelper at write time. |

Composite FK `(site_id, distinct, start, end)` references the matching
row in `site_client_fingerprints_count_summary`. Enforced by
application code, not by SQLite (SQLite FK enforcement is off by
default in MistHelper).

## State Transitions

N/A -- read-only endpoint. Each invocation produces a fresh aggregate
for the chosen window; repeated runs upsert by composite PK without
state side effects.

## SQLite DDL Snippet

`DataExporter` creates these tables automatically on first run; the DDL
is reproduced here for documentation and review purposes only. The
actual creation uses MistHelper's existing helper that maps the
registered PK strategy into a `CREATE TABLE IF NOT EXISTS` statement.

```sql
CREATE TABLE IF NOT EXISTS site_client_fingerprints_count_summary (
    site_id       TEXT    NOT NULL,
    distinct      TEXT    NOT NULL,
    start         INTEGER NOT NULL,
    end           INTEGER NOT NULL,
    limit         INTEGER NOT NULL,
    total         INTEGER NOT NULL,
    retrieved_at  TEXT    NOT NULL,
    PRIMARY KEY (site_id, distinct, start, end)
);

CREATE TABLE IF NOT EXISTS site_client_fingerprints_count_buckets (
    site_id       TEXT    NOT NULL,
    distinct      TEXT    NOT NULL,
    start         INTEGER NOT NULL,
    end           INTEGER NOT NULL,
    bucket_value  TEXT    NOT NULL,
    count         INTEGER NOT NULL,
    retrieved_at  TEXT    NOT NULL,
    PRIMARY KEY (site_id, distinct, start, end, bucket_value)
);

CREATE INDEX IF NOT EXISTS idx_site_client_fingerprints_count_buckets_site
    ON site_client_fingerprints_count_buckets (site_id);

CREATE INDEX IF NOT EXISTS idx_site_client_fingerprints_count_buckets_value
    ON site_client_fingerprints_count_buckets (bucket_value);
```

Note: `distinct`, `start`, `end`, and `limit` are SQLite reserved or
near-reserved words. The DDL above quotes nothing because SQLite
tolerates them as column identifiers in `CREATE TABLE`, but
application-level SQL generated by `DataExporter` wraps them in double
quotes (`"distinct"`, `"start"`, `"end"`, `"limit"`) for portability
when emitting `INSERT OR REPLACE`. Implementation must follow that
convention to avoid syntax errors on other engines.

## `ENDPOINT_PRIMARY_KEY_STRATEGIES` Entry

Add the following entry to the `ENDPOINT_PRIMARY_KEY_STRATEGIES`
dictionary in `MistHelper.py` (near the existing site-insights
operations). The bucket table is the primary persistence target; the
summary table is registered as a paired side-table.

```python
'countOrgClientFingerprints': {                              # operationId from OpenAPI / mistapi SDK
    'type': 'composite_pk',                                  # natural multi-column PK exists; no surrogate ID needed
    'primary_key': [                                         # composite PK columns for the bucket table
        'site_id',                                           # site supplied by user, not by API response
        'distinct',                                          # grouping field for this aggregate
        'start',                                             # window start echoed by API
        'end',                                               # window end echoed by API
        'bucket_value',                                      # per-bucket distinct value from results[]
    ],
    'indexes': [                                             # secondary indexes for common analyst queries
        'site_id',                                           # filter by site
        'bucket_value',                                      # filter / group by fingerprint value
    ],
    'table_name': 'site_client_fingerprints_count_buckets',  # primary table created on first run
    'related_tables': [                                      # paired side-table receives the summary row
        {
            'name': 'site_client_fingerprints_count_summary',
            'primary_key': ['site_id', 'distinct', 'start', 'end'],
            'indexes': ['site_id'],
        },
    ],
},
```

## Flattening Notes

The raw `200` response is a single dict:

```json
{
  "distinct": "model",
  "start": 1719600000,
  "end": 1719686400,
  "limit": 100,
  "total": 42,
  "results": [
    {"count": 17, "model": "iPhone15,2"},
    {"count": 9,  "model": "Pixel 8"}
  ]
}
```

The flattening logic produces:

- Exactly one summary row: `(site_id, distinct, start, end, limit,
  total, retrieved_at)`.
- Zero or more bucket rows, one per element of `results[]`. The bucket
  value is extracted as the single non-`count` key of each result
  object (per the OpenAPI `additionalProperties: {type: string}`
  contract). When `distinct` is empty, the bucket value defaults to the
  empty string.

When `results` is missing or empty, the summary row is still written
(with `total=0`) and no bucket rows are produced. The menu reports "no
fingerprint buckets returned" and exits cleanly.
