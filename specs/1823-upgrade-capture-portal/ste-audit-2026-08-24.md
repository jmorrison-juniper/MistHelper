# Task T228. The Simplified Technical English audit of the portal

**Date**: 2026-08-24.
**Scope**: every docstring, comment, message, and page string of
`src/upgrade_portal/` and `src/firmware/upgrade_service.py`.
**Guide**: `documentation/ASD-STE100_writing-guide.md`.

---

## 1. Why this record exists

The audit of 2026-08-20 found no audit record on disk. It also found the reason
the record was missing. `tools/ste_linter` grades a Markdown file and a Python
file, and it skips every other file type. T228 names the page strings, and every
page string of this portal lives in a Jinja template. Nothing had ever graded
one.

This record closes that gap and makes the grade repeatable.

---

## 2. What ran

| Surface | Command | Result |
| --- | --- | --- |
| The 40 Python modules | `python -m tools.ste_linter src/upgrade_portal/**/*.py` | Every module scores 97 or above |
| The 18 Jinja templates | `python scripts/extract_page_strings.py <file>` then the linter | 100 of 100, PASS |

The Python half held one error. `runtime/__init__.py` carried a 27-word
sentence, which broke rule 4.4. It is now three sentences, and the module moved
from 89 to 100. Every other module already scored 97 or above.

`scripts/extract_page_strings.py` turns the visible text of every template into
one Markdown file. It removes the Jinja statements, the Jinja comments, the
script bodies, the style bodies, and the tags. It keeps the sentences, and it
keeps the three attributes that a reader does meet, which are `placeholder`,
`title`, and `aria-label`.

The script writes one paragraph for each text node. That unit matters. An
operator meets each page string on its own, so a grade that joined two strings
would report a sentence that no reader ever sees. The first two drafts of the
script did join them, and both reported false breaches for that reason alone.

---

## 3. What the audit corrected

Four page strings broke a rule. Each one is now fixed.

| File | Before | After | Rule |
| --- | --- | --- | --- |
| `upgrade/stop.html` | "a stop cancels each upgrade that has not started" | "a stop cancels each upgrade that waits to start" | 3.6, simple tenses |
| `upgrade/stop.html` and `portal.js` | "No device was cancelled." | "The portal canceled no device." | 3.2 active voice, and American spelling |
| `upgrade/stop.html` and `portal.js` | "No device is writing firmware." | "No device writes firmware." | 3.6, simple tenses |
| `review/history.html` | One 26-word caption | Two sentences | 4.4, sentence length |

`portal.js` holds the same two sentences as the stop template, because the
script repaints that list after a stop. Both copies changed together, so the
page reads the same before and after the script runs.

One test comment carried the passive form of the same sentence. It changed with
the strings it describes.

## 4. What the audit left alone

Nine warnings remain, and every one is a false report of the linter. The record
names them so that a later reader does not chase them again.

| Line | Rule | Why the text stands |
| --- | --- | --- |
| Three warnings | STE-S7-WARNING | Each one states its consequence in the sentence after the signal word. The rule reads the first sentence alone. "Warning: the upgrade writes new firmware to devices and reboots each one. A device is offline while it reboots. The portal cannot undo a write." |
| Four warnings | STE-S2-NOUNCLUSTER | Each cluster spans a sentence boundary or a preposition, such as "lock state right now" and "one page holds rows". No cluster of four nouns exists in the text. |
| Two warnings | STE-S6-PARA | The unknown-state message of the lock banner runs to seven short sentences. Each sentence is one instruction, and a split would separate an instruction from its reason. |

## 4. The Python half, measured and not corrected

The page strings are the half that nothing had ever graded, and that half is now
clean. The Python half was already graded before this audit, and it holds one
open class.

| Reading | Number |
| --- | --- |
| Modules graded | 39 |
| Modules that pass the 80 floor of `ste-lint.yml` | 39 |
| Lowest module score | 94 |
| Sentences above the 25-word limit, rule 4.4 | 412 |

Every module passes the floor that continuous integration enforces, because the
linter weighs a score by word count and these modules carry many words. The 412
sentences are real all the same. They sit in the `Why:` blocks of docstrings and
in inline comments, and a sample of four confirmed that each one is prose and
not a field list that the parser joined.

The split of those 412 sentences is deferred, and this record states the reason
so that a later reader does not mistake the silence for a pass. The reason is
the one that T227 gives for the same class of finding. No gate enforces the
rule below a score of 80, every module already passes that gate, and the edit
touches 39 files of documentation span with no behavior change. A change that
wide belongs in its own pull request with its own review, where a reader can
judge the prose rather than the diff.

`runtime/__init__.py` is the exception that this audit did correct, because it
was the one module whose sentence section scored below 100.

## 5. How to run this audit again

```powershell
.\.venv\Scripts\python.exe scripts\extract_page_strings.py page-strings.md
.\.venv\Scripts\python.exe -m tools.ste_linter page-strings.md
```

Expect 100 of 100 and nine warnings. A new error, or a tenth warning, names a
page string that a change introduced.

Warning: never edit the extracted file. It is a report. Fix the template.
