# Phase 1 Quickstart: getMspAdmin

**Spec**: [spec.md](./spec.md)
**Plan**: [plan.md](./plan.md)
**Date**: 2026-06-29

This quickstart shows a developer how to run, exercise, and validate the new menu
item on a Windows 11 dev box. Container parity is identical (paths normalize via
`pathlib.Path` and `os.path.join`).

## Prerequisites

- Windows 11 with PowerShell 7+ (or any shell on Linux container).
- Python 3.13 or newer on PATH.
- Repository cloned at the worktree root referenced in `plan.md`.
- Working `.venv` activated:

  ```powershell
  .venv\Scripts\Activate.ps1
  ```

- `mistapi` 0.59+ installed:

  ```powershell
  python -m pip install --upgrade mistapi python-dotenv
  ```

## Required `.env` variables

Create or update `.env` in the repository root (git-ignored). Never commit this file.

```ini
MIST_HOST=api.mist.com
MIST_API_TOKEN=<your-mist-api-token>
MIST_MSP_ID=<your-default-msp-uuid>      # optional default for the msp_id prompt
MIST_ADMIN_ID=<your-default-admin-uuid>  # optional default for the admin_id prompt
```

Loading is handled by the existing `python-dotenv` bootstrap in `MistHelper.py`. The
API token is consumed by `mistapi.APISession` and is never written to logs or stdout.
PII fields returned by the endpoint (`email`, `phone`, `phone2`, `first_name`,
`last_name`) are persisted to the configured output backend but never echoed to log
output at any level.

## Expected output filenames

Files land under `data/` (the directory is enforced at runtime; create it with
`chmod -R 777 data/` on Linux first to satisfy the non-root container user).

- Summary CSV: `data/msp_<first-8-of-msp-uuid>_admin_<first-8-of-admin-uuid>.csv`
- Privileges CSV:
  `data/msp_<first-8-of-msp-uuid>_admin_<first-8-of-admin-uuid>_privileges.csv`
- SQLite: `data/mist_data.db`, tables `msp_admins` and `msp_admin_privileges`

## Skeleton of the new method

The full implementation is generated by `/speckit.implement`; this skeleton documents
the expected shape so that inline comment and action logging coverage can be reviewed
before the code is written. Every executable line carries a `#` comment (Constitution
VI), and every meaningful action is bracketed by `logging.info()` / `logging.debug()`
calls (Constitution VII).

```python
class MspAdminExportUtils:                                                          # new class, no wrapper function

    def export_msp_admin(self, msp_id=None, admin_id=None):                         # menu 57 entrypoint
        logging.info("Prompting for msp_id for MSP admin menu item")                # before-prompt action log
        msp_id = msp_id or safe_input(                                              # honor caller override else prompt user
            "MSP ID (UUID): ",                                                      # human-readable prompt text
            context="msp_admin:msp_id",                                             # SSH/container EOF context tag
            default=os.environ.get("MIST_MSP_ID", ""),                              # fall back to .env default
        )
        if not is_valid_uuid(msp_id):                                               # validate before any API call
            logging.warning("Invalid msp_id -- aborting menu 57")                   # log validation failure (no PII)
            return                                                                  # early return per safety-first

        logging.info("Prompting for admin_id for MSP admin menu item")              # before-prompt action log
        admin_id = admin_id or safe_input(                                          # honor caller override else prompt user
            "Admin ID (UUID): ",                                                    # human-readable prompt text
            context="msp_admin:admin_id",                                           # SSH/container EOF context tag
            default=os.environ.get("MIST_ADMIN_ID", ""),                            # fall back to .env default
        )
        if not is_valid_uuid(admin_id):                                             # validate before any API call
            logging.warning("Invalid admin_id -- aborting menu 57")                 # log validation failure (no PII)
            return                                                                  # early return per safety-first

        logging.info(                                                               # before-API-call action log
            "Fetching MSP admin %s for MSP %s", admin_id[:8], msp_id[:8],           # short prefixes only -- no full UUIDs
        )
        response = mistapi.api.v1.msps.admins.getMspAdmin(                          # actual SDK call
            self.apisession, msp_id, admin_id,                                      # two path params, no query string
        )
        body = response.data or {}                                                  # normalize None to empty dict
        privileges = body.get("privileges") or []                                   # default empty privilege list
        logging.debug(                                                              # after-API-call non-PII summary log
            "Admin record: role_count=%d via_sso=%s two_factor_verified=%s",
            len(privileges), body.get("via_sso"), body.get("two_factor_verified"),
        )

        logging.info("Flattening admin summary for admin %s", admin_id[:8])         # before-flatten action log
        summary_row = self._flatten_admin_summary(msp_id, body)                     # build one summary dict (incl. PII fields)
        logging.debug("Flattened 1 summary row")                                    # after-flatten count log

        logging.info("Flattening %d privilege rows", len(privileges))               # before-flatten action log
        privilege_rows = self._flatten_admin_privileges(msp_id, admin_id, privileges)  # one row per privilege grant
        logging.debug("Flattened %d privilege rows", len(privilege_rows))           # after-flatten count log

        logging.info("Writing MSP admin summary via DataExporter")                  # before-export action log
        DataExporter.write_with_format_selection(                                   # multi-backend write of summary
            [summary_row],                                                          # list-of-rows interface
            filename=f"msp_{msp_id[:8]}_admin_{admin_id[:8]}",                      # human-friendly stem
            api_function_name="getMspAdmin",                                        # PK strategy lookup key
        )

        logging.info("Writing MSP admin privileges via DataExporter")               # before-export action log
        DataExporter.write_with_format_selection(                                   # multi-backend write of privileges
            privilege_rows,                                                         # may be empty list when no privileges
            filename=f"msp_{msp_id[:8]}_admin_{admin_id[:8]}_privileges",           # human-friendly stem
            api_function_name="getMspAdminPrivileges",                              # MistHelper-internal sub-table key
        )
```

Helpers `_flatten_admin_summary` and `_flatten_admin_privileges` follow the same
comment- and log-density rules, stay under 25 lines, and live on the same
`MspAdminExportUtils` class -- no standalone wrapper functions. The privileges
helper expands `sitegroup` / `orggroup` scopes into one row per group ID per the
`scope_target` derivation rule documented in `data-model.md`.

## Quality gates (all must pass before commit)

Run these from the repository root with the venv active:

```powershell
python -m py_compile MistHelper.py        # 1. Syntax check (zero output = pass)
python -m ruff check MistHelper.py        # 2. Lint (zero violations = pass)
python -m black --check MistHelper.py     # 3. Format (zero diffs = pass; rerun without --check to auto-fix)
python MistHelper.py --test               # 4. Functional smoke test (menu 57 included)
```

The `--test` sweep automatically skips heavy/destructive operations (14, 18, 63-65,
90-100). Menu 57 sits inside the standard sweep range, so a green run confirms the
new item works end to end against the MSP / admin configured in `.env`.
