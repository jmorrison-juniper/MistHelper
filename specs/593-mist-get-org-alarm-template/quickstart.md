# Phase 1 Quickstart: getOrgAlarmTemplate

**Spec**: [spec.md](./spec.md)
**Plan**: [plan.md](./plan.md)
**Date**: 2026-06-29

This quickstart shows a developer how to run, exercise, and validate the new menu
item on a Windows 11 dev box. Container parity is identical (paths normalize via
`pathlib.Path` and `os.path.join`).

## Prerequisites

- Windows 11 with PowerShell 7+ (or any shell on Linux container).
- Python 3.13 or newer on PATH.
- Repository cloned at the worktree root referenced in `plan.md`.
- Working `.venv` activated:

  ```powershell
  .venv\Scripts\Activate.ps1
  ```

- `mistapi` 0.59+ installed:

  ```powershell
  python -m pip install --upgrade mistapi python-dotenv
  ```

- `data/` directory exists with write permission:

  ```powershell
  if (-not (Test-Path data)) { New-Item -ItemType Directory -Path data | Out-Null }
  # On Linux container hosts: chmod -R 777 data/ before first run
  ```

## Required `.env` variables

Create or update `.env` in the repository root (git-ignored). Never commit this
file.

```ini
MIST_HOST=api.mist.com
MIST_API_TOKEN=<your-mist-api-token>
MIST_ORG_ID=<your-default-org-uuid>     # optional default for the org_id prompt
```

Loading is handled by the existing `python-dotenv` bootstrap in `MistHelper.py`.
The API token is consumed by `mistapi.APISession` and is never written to logs or
stdout.

## Expected output filenames

Files land under `data/` (the directory is enforced at runtime).

- Parent CSV: `data/org_<first-8-of-org-uuid>_alarm_template_<first-8-of-template-uuid>.csv`
- Rules CSV:
  `data/org_<first-8-of-org-uuid>_alarm_template_<first-8-of-template-uuid>_rules.csv`
- SQLite: `data/mist_data.db`, tables `org_alarm_templates` (parent) and
  `org_alarm_template_rules` (child).

## Skeleton of the new method

The full implementation is generated by `/speckit.implement`; this skeleton
documents the expected shape so that inline comment and action logging coverage
can be reviewed before the code is written. Every executable line carries a `#`
comment (Constitution VI), and every meaningful action is bracketed by
`logging.info()` / `logging.debug()` calls (Constitution VII).

```python
class TemplateExportUtils:                                                          # existing class, no new wrapper

    def export_org_alarm_template(self, org_id=None, alarmtemplate_id=None):        # menu 38 entrypoint
        logging.info("Prompting for org_id for alarm template menu item")           # before-prompt action log
        org_id = org_id or safe_input(                                              # honor caller override else prompt user
            "Org ID (UUID): ",                                                      # human-readable prompt text
            context="org_alarm_template:org_id",                                    # SSH/container EOF context tag
            default=os.environ.get("MIST_ORG_ID", ""),                              # fall back to .env default
        )
        if not is_valid_uuid(org_id):                                               # validate before any API call
            logging.warning("Invalid org_id %s -- aborting menu 38", org_id)        # log validation failure (no traceback)
            return                                                                  # early return per safety-first principle

        logging.info("Prompting for alarmtemplate_id for menu 38")                  # before-prompt action log
        alarmtemplate_id = alarmtemplate_id or safe_input(                          # honor caller override else prompt
            "Alarm Template ID (UUID): ",                                           # human-readable prompt text
            context="org_alarm_template:alarmtemplate_id",                          # SSH/container EOF context tag
            default="",                                                             # no env default (per-object UUID)
        )
        if not is_valid_uuid(alarmtemplate_id):                                     # validate before any API call
            logging.warning("Invalid alarmtemplate_id %s", alarmtemplate_id)        # log validation failure (no traceback)
            return                                                                  # early return per safety-first principle

        logging.info(                                                               # before-API-call action log
            "Fetching alarm template %s for org %s",
            alarmtemplate_id[:8], org_id[:8],                                       # log only short prefixes
        )
        response = mistapi.api.v1.orgs.alarmtemplates.getOrgAlarmTemplate(          # actual SDK call
            self.apisession, org_id, alarmtemplate_id,                              # both required path params
        )
        body = response.data or {}                                                  # normalize None to empty dict
        rules = body.get("rules") or {}                                             # rules is a dynamic-key map
        logging.debug(                                                              # after-API-call summary log
            "Alarm template %s has %d rules",
            alarmtemplate_id[:8], len(rules),
        )

        logging.info("Flattening parent alarm template payload")                    # before-flatten action log
        parent_row = self._flatten_alarm_template_parent(org_id, body)              # one parent dict
        logging.debug("Flattened 1 parent alarm template row")                      # after-flatten count log

        logging.info("Flattening %d alarm template rule rows", len(rules))          # before-flatten action log
        rule_rows = self._flatten_alarm_template_rules(                             # one row per rule key
            org_id, alarmtemplate_id, rules,
        )
        logging.debug("Flattened %d alarm template rule rows", len(rule_rows))      # after-flatten count log

        logging.info("Writing alarm template parent via DataExporter")              # before-export action log
        DataExporter.write_with_format_selection(                                   # multi-backend write
            [parent_row],                                                           # list-of-rows interface
            filename=f"org_{org_id[:8]}_alarm_template_{alarmtemplate_id[:8]}",     # human-friendly stem
            api_function_name="getOrgAlarmTemplate",                                # PK strategy lookup key
        )

        logging.info("Writing alarm template rules via DataExporter")               # before-export action log
        DataExporter.write_with_format_selection(                                   # second multi-backend write
            rule_rows,                                                              # may be empty list when no rules
            filename=f"org_{org_id[:8]}_alarm_template_{alarmtemplate_id[:8]}_rules",  # human-friendly stem
            api_function_name="getOrgAlarmTemplateRules",                           # MistHelper-internal sub-table key
        )
```

Helpers `_flatten_alarm_template_parent` and `_flatten_alarm_template_rules`
follow the same comment- and log-density rules, stay under 15 lines each, and
live on the same `TemplateExportUtils` class -- no standalone wrapper
functions. Both helpers convert booleans to 0/1 INTEGERs and join
`additional_emails` arrays with `"|"` for CSV-friendly storage.

## Quality gates (all must pass before commit)

Run these from the repository root with the venv active:

```powershell
python -m py_compile MistHelper.py        # 1. Syntax check (zero output = pass)
python -m ruff check MistHelper.py        # 2. Lint (zero violations = pass)
python -m black --check MistHelper.py     # 3. Format (zero diffs = pass; rerun without --check to auto-fix)
python MistHelper.py --test               # 4. Functional smoke test (menu 38 included)
```

The `--test` sweep automatically skips heavy/destructive operations (14, 18,
63-65, 90-100). Menu 38 sits inside the standard sweep range, so a green run
confirms the new item works end to end against the org configured in `.env`.
The test harness either reads `MIST_ALARMTEMPLATE_ID` from `.env` for the
template prompt, or auto-discovers a valid template UUID by calling
`listOrgAlarmTemplates` once and using the first returned `id`.
