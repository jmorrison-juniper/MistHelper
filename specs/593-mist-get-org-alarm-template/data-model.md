## Source

API response schema lifted from
`documentation/api/orgs/GET_orgs_org_id_alarmtemplates_alarmtemplate_id.md`
(200 OK body).

## Entities

The endpoint returns a single JSON `Alarm Template` object whose nested `rules`
property is a dynamic-key map. MistHelper splits this into two logical entities for
clean multi-backend persistence and to keep the schema queryable from plain SQL.

### Entity 1: `AlarmTemplate`

One row per (org, alarm template). Sourced from the top-level fields of the
response, with the nested `delivery` object flattened by dotted-key prefix.

| Field                          | Type     | Source                              | PK? | FK?              | Notes |
|--------------------------------|----------|-------------------------------------|-----|------------------|-------|
| `id`                           | TEXT     | API `id`                            | YES | --               | UUID generated by Mist; stable for the life of the template. |
| `org_id`                       | TEXT     | API `org_id` (validated against path) | -- | sites.org_id     | UUID; indexed for fast org-scoped lookups. |
| `name`                         | TEXT     | API `name`                          | --  | --               | Human-readable template name. |
| `created_time`                 | REAL     | API `created_time`                  | --  | --               | Epoch seconds (read-only). |
| `modified_time`                | REAL     | API `modified_time`                 | --  | --               | Epoch seconds (read-only). |
| `delivery_enabled`             | INTEGER  | API `delivery.enabled`              | --  | --               | 0/1 boolean. **Required** in source schema. |
| `delivery_to_org_admins`       | INTEGER  | API `delivery.to_org_admins`        | --  | --               | 0/1 boolean. May be absent -> NULL. |
| `delivery_to_site_admins`      | INTEGER  | API `delivery.to_site_admins`       | --  | --               | 0/1 boolean. May be absent -> NULL. |
| `delivery_additional_emails`   | TEXT     | API `delivery.additional_emails`    | --  | --               | Pipe-joined list (e.g. `"a@x.com|b@y.com"`) for CSV friendliness. |
| `rule_count`                   | INTEGER  | len(API `rules`)                    | --  | --               | Convenience count of the `rules` map (number of alarm keys configured). |
| `polled_at_utc`                | TEXT     | MistHelper clock                    | --  | --               | ISO8601 UTC timestamp of the poll, for audit. |

### Entity 2: `AlarmTemplateRule`

Zero or more rows per alarm template. One row per alarm key in the response's
`rules` map. Sourced from each `(rule_name, rule_payload)` pair, with the nested
`delivery` object flattened by dotted-key prefix.

| Field                          | Type     | Source                                   | PK? | FK?                          | Notes |
|--------------------------------|----------|------------------------------------------|-----|------------------------------|-------|
| `alarmtemplate_id`             | TEXT     | MistHelper context (parent `id`)         | YES | org_alarm_templates.id       | UUID. |
| `rule_name`                    | TEXT     | API `rules` map key                      | YES | --                           | Alarm-key string (e.g. `"ap_offline"`, `"bad_cable"`). |
| `org_id`                       | TEXT     | MistHelper context (parent `org_id`)     | --  | org_alarm_templates.org_id   | UUID; indexed. |
| `enabled`                      | INTEGER  | API `rules[name].enabled`                | --  | --                           | 0/1 boolean. |
| `delivery_enabled`             | INTEGER  | API `rules[name].delivery.enabled`       | --  | --                           | 0/1 boolean; NULL when per-rule delivery omitted. |
| `delivery_to_org_admins`       | INTEGER  | API `rules[name].delivery.to_org_admins` | --  | --                           | 0/1 boolean; NULLable. |
| `delivery_to_site_admins`      | INTEGER  | API `rules[name].delivery.to_site_admins`| --  | --                           | 0/1 boolean; NULLable. |
| `delivery_additional_emails`   | TEXT     | API `rules[name].delivery.additional_emails` | -- | --                       | Pipe-joined string; NULLable. |
| `polled_at_utc`                | TEXT     | MistHelper clock                         | --  | --                           | ISO8601 UTC of the poll. |

## State Transitions

N/A -- this is a read-only endpoint. The underlying alarm template is configured
via the corresponding `PUT /api/v1/orgs/{org_id}/alarmtemplates/{alarmtemplate_id}`
operation (out of scope for this spec). MistHelper does not drive any state
transition here; it merely captures snapshots. Each poll overwrites the prior
snapshot for the same `id` (parent) and `(alarmtemplate_id, rule_name)` (child)
tuples via SQLite `INSERT OR REPLACE`.

## SQLite DDL

```sql
-- Parent table: one row per alarm template, keyed by the Mist-provided UUID.
CREATE TABLE IF NOT EXISTS org_alarm_templates (
    id                          TEXT     NOT NULL PRIMARY KEY,
    org_id                      TEXT     NOT NULL,
    name                        TEXT,
    created_time                REAL,
    modified_time               REAL,
    delivery_enabled            INTEGER,
    delivery_to_org_admins      INTEGER,
    delivery_to_site_admins     INTEGER,
    delivery_additional_emails  TEXT,
    rule_count                  INTEGER,
    polled_at_utc               TEXT
);

CREATE INDEX IF NOT EXISTS idx_org_alarm_templates_org_id
    ON org_alarm_templates (org_id);

CREATE INDEX IF NOT EXISTS idx_org_alarm_templates_name
    ON org_alarm_templates (name);

-- Child table: one row per (template, alarm key) pair from the rules map.
CREATE TABLE IF NOT EXISTS org_alarm_template_rules (
    alarmtemplate_id            TEXT     NOT NULL,
    rule_name                   TEXT     NOT NULL,
    org_id                      TEXT     NOT NULL,
    enabled                     INTEGER,
    delivery_enabled            INTEGER,
    delivery_to_org_admins      INTEGER,
    delivery_to_site_admins     INTEGER,
    delivery_additional_emails  TEXT,
    polled_at_utc               TEXT,
    PRIMARY KEY (alarmtemplate_id, rule_name),
    FOREIGN KEY (alarmtemplate_id)
        REFERENCES org_alarm_templates(id)
);

CREATE INDEX IF NOT EXISTS idx_org_alarm_template_rules_org_id
    ON org_alarm_template_rules (org_id);

CREATE INDEX IF NOT EXISTS idx_org_alarm_template_rules_rule_name
    ON org_alarm_template_rules (rule_name);
```

`DataExporter.write_with_format_selection()` is responsible for emitting the
equivalent DDL on first write per backend (SQLite via `CREATE TABLE IF NOT
EXISTS`, ArangoDB via collection upsert, Redis via key namespacing). MistHelper
does not run the DDL directly from the menu method.

## ENDPOINT_PRIMARY_KEY_STRATEGIES Entries

Add the following two entries to the existing `ENDPOINT_PRIMARY_KEY_STRATEGIES`
dictionary in `MistHelper.py` (two simple inserts into the dict literal -- no
structural change to the dict definition).

```python
ENDPOINT_PRIMARY_KEY_STRATEGIES = {
    # ... existing entries ...

    # Parent: one row per Mist-managed alarm template, keyed by Mist UUID.
    'getOrgAlarmTemplate': {                                                        # operationId from OpenAPI
        'type': 'natural_pk',                                                       # Mist-supplied UUID is stable
        'primary_key': ['id'],                                                      # UUID guaranteed unique by Mist
        'indexes': ['org_id', 'name'],                                              # fast scoped + by-name lookups
        'table': 'org_alarm_templates',                                             # target SQLite table for parent rows
    },

    # Child: per-rule rows produced from the parent template's `rules` map.
    'getOrgAlarmTemplateRules': {                                                   # MistHelper-internal sub-table id
        'type': 'composite_pk',                                                     # composite of template id + rule name
        'primary_key': ['alarmtemplate_id', 'rule_name'],                           # uniquely identifies a rule snapshot
        'indexes': ['org_id', 'rule_name'],                                         # fast org-scoped + by-rule lookups
        'table': 'org_alarm_template_rules',                                        # target SQLite table for child rows
    },
}
```

The `getOrgAlarmTemplateRules` key is a MistHelper-internal identifier (the Mist
API has no operationId for it -- it is a flattened sub-map of the parent
response). This naming pattern matches how MistHelper already splits other
endpoints whose response contains nested arrays or dynamic-key maps.

## Notes on Cross-Endpoint Compatibility

The `org_alarm_templates` parent table is the same physical SQLite table populated
by the existing `listOrgAlarmTemplates` menu item (operationId
`listOrgAlarmTemplates`). The two endpoints share `id` as the natural primary
key, so rows upsert cleanly regardless of which menu path inserted them. The
single-template GET captures the **full** template object (including the `rules`
map), while the list endpoint returns the same parent fields plus the same nested
`rules` map per template -- DataExporter must therefore consistently flatten
`rules` into `org_alarm_template_rules` for both endpoints. This is already the
documented MistHelper convention for endpoints that share a response shape.
