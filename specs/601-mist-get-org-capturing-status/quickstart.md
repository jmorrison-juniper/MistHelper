# Phase 1 Quickstart: getOrgCapturingStatus

**Spec**: [spec.md](./spec.md)
**Plan**: [plan.md](./plan.md)
**Date**: 2026-06-30

This quickstart shows a developer how to run, exercise, and validate the new menu
item on a Windows 11 dev box. Container parity is identical (paths normalize via
`pathlib.Path` and `os.path.join`).

## Prerequisites

- Windows 11 with PowerShell 7+ (or any shell on Linux container).
- Python 3.13 or newer on PATH.
- Repository cloned at the worktree root referenced in `plan.md`.
- Working `.venv` activated:

  ```powershell
  .venv\Scripts\Activate.ps1
  ```

- `mistapi` 0.59+ installed:

  ```powershell
  python -m pip install --upgrade mistapi python-dotenv
  ```

## Required `.env` variables

Create or update `.env` in the repository root (git-ignored). Never commit this
file.

```ini
MIST_HOST=api.mist.com
MIST_API_TOKEN=<your-mist-api-token>
MIST_ORG_ID=<your-default-org-uuid>   # optional default for the org_id prompt
```

Loading is handled by the existing `python-dotenv` bootstrap in `MistHelper.py`.
The API token is consumed by `mistapi.APISession` and is never written to logs or
stdout.

## Expected output filenames

Files land under `data/` (the directory is enforced at runtime; on Linux first
ensure `chmod -R 777 data/` so the non-root container user can write).

- Summary CSV: `data/org_<first-8-of-org-uuid>_capturing_status.csv`
- Per-AP CSV: `data/org_<first-8-of-org-uuid>_capturing_status_aps.csv`
  (emitted whenever the response contains a non-empty `pcap_aps` map; if `pcap_aps`
  is absent or empty, the file is not written and DataExporter logs "0 rows")
- SQLite: `data/mist_data.db`, tables `org_pcap_capture_status` and
  `org_pcap_capture_status_aps`

## Skeleton of the new method

The full implementation is generated by `/speckit.implement`; this skeleton
documents the expected shape so inline-comment and action-logging coverage can be
reviewed before code is written. Every executable line carries a `#` comment
(Constitution VI), and every meaningful action is bracketed by `logging.info()` /
`logging.debug()` calls (Constitution VII).

```python
class PacketCaptureManager:                                                         # existing class, no new wrapper

    def export_org_capturing_status(self, org_id=None):                             # menu 96 entrypoint
        logging.info("Prompting for org_id for capturing-status menu item")         # before-prompt action log
        org_id = org_id or safe_input(                                              # honor caller override else prompt user
            "Org ID (UUID): ",                                                      # human-readable prompt text
            context="org_capturing_status:org_id",                                  # SSH/container EOF context tag
            default=os.environ.get("MIST_ORG_ID", ""),                              # fall back to .env default
        )
        if not is_valid_uuid(org_id):                                               # validate before any API call
            logging.warning("Invalid org_id %s -- aborting menu 96", org_id)        # log validation failure (no traceback)
            return                                                                  # early return per safety-first principle

        logging.info("Fetching capturing status for org %s", org_id)                # before-API-call action log
        response = mistapi.api.v1.orgs.pcaps.capture.getOrgCapturingStatus(         # actual SDK call (URL-based path)
            self.apisession, org_id,                                                # only path param is org_id
        )
        if response.status_code == 404:                                             # 404 = no active capture per enriched doc
            logging.warning("No active capture for org %s (404)", org_id)           # benign, not an error
            logging.info("Wrote 0 rows; nothing to flatten or persist")             # explicit no-op log
            return                                                                  # clean exit, no traceback

        body = response.data or {}                                                  # normalize None to empty dict
        logging.debug(                                                              # after-API-call summary log
            "Capture id=%s type=%s started_time=%s num_packets=%s",
            body.get("id"), body.get("type"),
            body.get("started_time"), body.get("num_packets"),
        )

        logging.info("Flattening capture summary for org %s", org_id)               # before-flatten action log
        summary_row = self._flatten_capture_summary(org_id, body)                   # build one summary dict
        logging.debug("Flattened 1 summary row")                                    # after-flatten count log

        per_ap_rows = self._flatten_capture_aps(                                    # one row per AP MAC in pcap_aps
            org_id, body.get("id"), body.get("pcap_aps") or {},
        )
        logging.info("Flattening %d per-AP detail rows", len(per_ap_rows))          # before-(second-)flatten action log
        logging.debug("Flattened %d per-AP detail rows", len(per_ap_rows))          # after-flatten count log

        logging.info("Writing capture status summary via DataExporter")             # before-export action log
        DataExporter.write_with_format_selection(                                   # multi-backend write (CSV/SQLite/Arango)
            [summary_row],                                                          # list-of-rows interface
            filename=f"org_{org_id[:8]}_capturing_status",                          # human-friendly stem
            api_function_name="getOrgCapturingStatus",                              # PK strategy lookup key
        )
        if per_ap_rows:                                                             # only write detail file when non-empty
            logging.info("Writing capture status per-AP detail via DataExporter")   # before-export action log
            DataExporter.write_with_format_selection(                               # second multi-backend write
                per_ap_rows,                                                        # one row per AP MAC
                filename=f"org_{org_id[:8]}_capturing_status_aps",                  # human-friendly stem
                api_function_name="getOrgCapturingStatusAps",                       # MistHelper-internal sub-table key
            )
```

Helpers `_flatten_capture_summary` and `_flatten_capture_aps` follow the same
comment-and-log-density rules, stay under 25 lines, and live on the same
`PacketCaptureManager` class -- no standalone wrapper functions.

## Quality gates (all must pass before commit)

Run these from the repository root with the venv active:

```powershell
python -m py_compile MistHelper.py        # 1. Syntax check (zero output = pass)
python -m ruff check MistHelper.py        # 2. Lint (zero violations = pass)
python -m black --check MistHelper.py     # 3. Format (zero diffs = pass; rerun without --check to auto-fix)
python MistHelper.py --test               # 4. Functional smoke test (menu 96 included)
```

The `--test` sweep automatically skips heavy/destructive operations (14, 18, 63-65,
90-100). Menu 96 sits at the top of the Interactive Safe range and is inside the
standard sweep, so a green run confirms the new item works end-to-end against the
org configured in `.env`.
