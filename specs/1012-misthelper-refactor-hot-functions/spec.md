# Feature Specification: MistHelper.py Refactor Extraction — Hot-Function Third Pass (Bounded Single-PR)

**Feature Branch**: `1012-misthelper-refactor-hot-functions`
**Created**: 2026-07-06
**Status**: Draft
**Predecessors**:
- [`1010-misthelper-refactor-extraction`](../1010-misthelper-refactor-extraction/spec.md) — first-pass Unused + Single-Use bucket clearance (13 PRs)
- [`1011-misthelper-refactor-low-use`](../1011-misthelper-refactor-low-use/spec.md) — second-pass 20-candidate Low-Use serial workflow (in flight)

**Input**: User description: "Third-pass Hot-Function extraction from MistHelper.py. Bounded, single-PR initiative (unlike 1011's serial-PR workflow). Exactly three actions in one PR: (1) skip-pin `tqdm`, (2) extract `is_debug_mode` to `src/refactors/is_debug_mode.py`, (3) extract `execute_with_connection_pool_management` + its three `_pool_*` helpers to `src/refactors/connection_pool_executor.py`. Deliberately overrides 1011's SC-009 Hot-bucket source-extraction prohibition for these three specific candidates."

## Predecessor Context

Initiative 1010 established the extraction contract (FR-003 no wrappers, FR-005 class-body seams, FR-007 project non-negotiables, FR-011 CI-clean merge discipline). Initiative 1011 extended that contract across 20 Low-Use candidates with a serial per-PR workflow and, in its SC-009, explicitly forbade extracting Hot-bucket **source** symbols:

> **1011 SC-009**: Zero symbols from the Hot bucket (4+ callers) are extracted as source symbols during this second pass.

Initiative 1012 deliberately narrows the SC-009 prohibition to the second pass only. Three specific Hot-bucket entries are extracted or skip-pinned in this third pass with per-candidate rationale documented below. The 1011 SC-009 constraint is **not** repealed for the remainder of the Hot bucket (77 candidates still deferred); each future Hot-source extraction requires its own case-by-case justification in a new SpecKit revision.

## Scope Boundary

Exactly three symbol-level actions land in exactly one pull request. No other Hot-bucket candidates are touched in this initiative. No new features, new commands, or refactor-analyzer modifications are in scope.

The three actions:

| # | Symbol | Current Location | Action | Landing |
|---|--------|------------------|--------|---------|
| 1 | `tqdm` (fallback shim) | `MistHelper.py:635-637` (~3 LoC, 43 refs) | Skip-pin via analyzer `--skip` CLI flag | Remains in place; catalogued as Skipped |
| 2 | `is_debug_mode` (module-level function) + `EnvironmentUtils.is_debug_mode` static-method wrapper at `MistHelper.py:5891-5900` | `MistHelper.py:318-320` (~3 LoC, 12 direct refs across 2 files) + wrapper at 5891-5900 (0 external callers per spec-time verification) | Extract module-level function AND delete wrapper outright | New `IsDebugMode` class in `src/refactors/is_debug_mode.py`; wrapper simply removed |
| 3 | `execute_with_connection_pool_management` + `_pool_prepare_execution` + `_pool_run_all_batches` + `_pool_apply_retry` | `MistHelper.py:7503-7576` (~74 LoC total, 7 direct refs to public function across 3 files; helper family is MistHelper-private) | Extract as a co-located family | New `ConnectionPoolExecutor` class in `src/refactors/connection_pool_executor.py` |

## User Scenarios & Testing *(mandatory)*

### User Story 1 — Skip-pin the `tqdm` fallback shim so it moves to the Skipped bucket (Priority: P1)

The three-line `tqdm` fallback at `MistHelper.py:635-637` is a bootstrap-time no-op that returns `iterable` unchanged. It exists solely so any module-level code executed before `GlobalImportManager` runs still resolves the name `tqdm`. Once `GlobalImportManager` finishes, it rebinds `tqdm = real_tqdm` at module scope. If the fallback were relocated to a separate file, the rebind executed inside `MistHelper.py`'s namespace would not propagate back to the relocated definition, and 43 downstream references would silently keep pointing at the no-op shim. This is the same load-order pathology that keeps `GlobalImportManager` in the analyzer's curated `SKIP_ALWAYS` set.

**Why this priority**: Zero-code-change action delivering a permanent analyzer contract for a symbol that must never be extracted. Land it first so all analyzer reruns downstream of this PR file `tqdm` in the Skipped bucket instead of continually re-surfacing it as a 43-reference Hot candidate.

**Independent Test**: After the PR merges, run `python -m tools.refactor_analyzer MistHelper.py --skip tqdm -o refactor_candidates.md`; `tqdm` appears in the Skipped section (alongside `GlobalImportManager`) with the recorded bootstrap-pin rationale, and does not appear in the Hot bucket.

**Acceptance Scenarios**:

1. **Given** the freshly regenerated catalog on the merge commit, **When** the analyzer runs with `--skip tqdm --skip GlobalImportManager`, **Then** both names appear in the Skipped bucket and neither appears in Hot, Low-Use, Single-Use, or Unused.
2. **Given** documentation for the initiative, **When** a future contributor reads `refactor_candidates.md` or this spec, **Then** the rationale for the pin is discoverable in one hop: "load-order dependency — `GlobalImportManager` rebinds `tqdm` at module scope; a relocated definition would not receive that rebind."
3. **Given** the PR diff, **When** reviewed, **Then** the only source-file change relating to `tqdm` is a **mandatory** NOTE breadcrumb comment adjacent to line 635 following the pinned extraction-site template (per FR-024, Clarifications Q5, 2026-07-06): `# NOTE: tqdm extracted to <skip-pin (analyzer --skip flag)>. See specs/1012-misthelper-refactor-hot-functions/spec.md.` The fallback body itself remains byte-identical and untouched; the breadcrumb's presence is verified by SC-014.
