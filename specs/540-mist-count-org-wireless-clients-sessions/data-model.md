# Phase 1 Data Model: countOrgWirelessClientsSessions

**Spec**: [spec.md](./spec.md) | **Plan**: [plan.md](./plan.md) | **Date**: 2026-06-29

Source schema: `documentation/api/orgs/GET_orgs_org_id_clients_sessions_count.md`
section "Response 200".

## Entities

The 200 response is a single JSON object with two distinct levels: a flat
top-level summary, and a `results` array of count buckets. MistHelper models
these as two flat entities so each upserts cleanly under
`DataExporter.write_with_format_selection()`.

### Entity 1: CountSessionsSummary

One row per menu invocation -- captures the query envelope returned by the API.

| Field                    | Type    | Source                | Notes                                            |
|--------------------------|---------|-----------------------|--------------------------------------------------|
| misthelper_internal_id   | INTEGER | autogenerated         | Primary key (auto-increment).                    |
| org_id                   | TEXT    | path param            | Indexed. UUID of the org queried.                |
| distinct                 | TEXT    | response.distinct     | Indexed. The attribute aggregated on.            |
| start                    | INTEGER | response.start        | Epoch seconds, window start.                     |
| end                      | INTEGER | response.end          | Epoch seconds, window end.                       |
| duration                 | TEXT    | client-supplied       | The exact `duration` value passed to the SDK.    |
| limit                    | INTEGER | response.limit        | Echoed page size used by the API.                |
| total                    | INTEGER | response.total        | Total bucket count across the result set.        |
| retrieved_at             | TEXT    | client-supplied       | ISO-8601 UTC timestamp of the invocation.        |

- **Primary key**: `misthelper_internal_id`
- **Foreign keys**: `org_id` references the `org` natural key elsewhere in the
  catalog but is enforced only at the application layer; no `FOREIGN KEY`
  clause in the DDL (consistent with sibling `count_*` tables).
- **State transitions**: N/A -- read-only endpoint; rows are append-only
  snapshots, one per invocation.

### Entity 2: CountSessionsResult

One row per bucket inside `response.results`.

| Field                    | Type    | Source                       | Notes                                                                          |
|--------------------------|---------|------------------------------|--------------------------------------------------------------------------------|
| misthelper_internal_id   | INTEGER | autogenerated                | Primary key (auto-increment).                                                  |
| summary_id               | INTEGER | parent summary row           | Indexed FK-by-convention to `count_org_wireless_clients_sessions_summary`.     |
| org_id                   | TEXT    | path param                   | Indexed. Repeated on every result row for analytical convenience.              |
| distinct                 | TEXT    | response.distinct            | Indexed. The attribute name aggregated on.                                     |
| bucket_value             | TEXT    | response.results[i] addProp  | The value of the distinct attribute for this bucket (e.g. `"Corp-Guest"`).     |
| count                    | INTEGER | response.results[i].count    | The number of sessions in this bucket.                                         |
| retrieved_at             | TEXT    | client-supplied              | ISO-8601 UTC timestamp matching the summary row.                               |

- **Primary key**: `misthelper_internal_id`
- **Foreign keys**: `summary_id` references
  `count_org_wireless_clients_sessions_summary.misthelper_internal_id` at the
  application layer only.
- **State transitions**: N/A -- read-only endpoint.

### Schema-level note: `additionalProperties`

The response's `results[*]` schema declares `additionalProperties: {type:
"string"}` in addition to the required `count` integer. In practice the
extra key is always exactly one string property whose name equals the
`distinct` attribute the client asked for, and whose value is the bucket
label. MistHelper extracts that single extra key into the
`bucket_value` column and discards the original property name, which is
already captured in the row's `distinct` column. This keeps the SQLite
schema fixed regardless of which `distinct` attribute the user selects.

## SQLite DDL Snippets

`DataExporter` generates these CREATE TABLE statements on first write. They
are reproduced here for review.

```sql
-- Summary: one row per menu invocation.
CREATE TABLE IF NOT EXISTS count_org_wireless_clients_sessions_summary (
    misthelper_internal_id INTEGER PRIMARY KEY AUTOINCREMENT,
    org_id                 TEXT NOT NULL,
    distinct               TEXT NOT NULL,
    start                  INTEGER,
    end                    INTEGER,
    duration               TEXT,
    limit                  INTEGER,
    total                  INTEGER,
    retrieved_at           TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_count_sessions_summary_org
    ON count_org_wireless_clients_sessions_summary(org_id);
CREATE INDEX IF NOT EXISTS idx_count_sessions_summary_distinct
    ON count_org_wireless_clients_sessions_summary(distinct);

-- Per-bucket result rows.
CREATE TABLE IF NOT EXISTS count_org_wireless_clients_sessions_results (
    misthelper_internal_id INTEGER PRIMARY KEY AUTOINCREMENT,
    summary_id             INTEGER NOT NULL,
    org_id                 TEXT NOT NULL,
    distinct               TEXT NOT NULL,
    bucket_value           TEXT,
    count                  INTEGER NOT NULL,
    retrieved_at           TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_count_sessions_results_summary
    ON count_org_wireless_clients_sessions_results(summary_id);
CREATE INDEX IF NOT EXISTS idx_count_sessions_results_org
    ON count_org_wireless_clients_sessions_results(org_id);
CREATE INDEX IF NOT EXISTS idx_count_sessions_results_distinct
    ON count_org_wireless_clients_sessions_results(distinct);
```

Note: `distinct` and `limit` are SQL reserved-ish words in some engines.
SQLite accepts them as bare identifiers; if portability to other engines is
ever required, switch to `"distinct"` / `"limit"` quoted identifiers in the
generated DDL.

## ENDPOINT_PRIMARY_KEY_STRATEGIES Entry

This entry already exists in `MistHelper.py` at line ~4582 and is reused
verbatim. No new addition is required.

```python
"countOrgWirelessClientsSessions": {
    "type": "auto_increment_with_unique",
    "primary_key": ["misthelper_internal_id"],
    "indexes": ["org_id", "distinct"],
    "unique_constraints": [],
    "description": "Wireless client session count aggregates",
},
```

The same strategy applies to both the `_summary` and `_results` tables: each
row is a distinct append-only snapshot keyed by the
auto-increment `misthelper_internal_id`. Per-run idempotency is provided by
the client-supplied `retrieved_at` timestamp; duplicate detection across
runs is out of scope for an aggregation endpoint.

## Validation Rules

- `org_id` MUST match the Mist UUID pattern
  `^[0-9a-fA-F]{8}-([0-9a-fA-F]{4}-){3}[0-9a-fA-F]{12}$` before the SDK call.
- `distinct` MUST be one of the documented values in the contract; on
  invalid input MistHelper logs a `WARNING` and falls back to `ssid`.
- `duration` MUST match `^\\d+[smhdw]$` (e.g. `1d`, `7d`, `2w`, `30m`);
  invalid input falls back to `1d` with a `WARNING`.
- `count` in any result row MUST be a non-negative integer; rows failing
  this check are dropped with a `WARNING` and a count summary logged.
