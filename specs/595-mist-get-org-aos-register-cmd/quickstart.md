# Phase 1 Quickstart: getOrgAosRegisterCmd

**Spec**: [spec.md](./spec.md)
**Plan**: [plan.md](./plan.md)
**Date**: 2026-06-29

This quickstart shows a developer how to run, exercise, and validate the new menu
item on a Windows 11 dev box. Container parity is identical (paths normalize via
`pathlib.Path` and `os.path.join`).

## Prerequisites

- Windows 11 with PowerShell 7+ (or any shell on Linux container).
- Python 3.13 or newer on PATH.
- Repository cloned at the worktree root referenced in `plan.md`.
- Working `.venv` activated:

  ```powershell
  .venv\Scripts\Activate.ps1
  ```

- `mistapi` 0.59+ installed:

  ```powershell
  python -m pip install --upgrade mistapi python-dotenv
  ```

## Required `.env` variables

Create or update `.env` in the repository root (git-ignored). Never commit this
file.

```ini
MIST_HOST=api.mist.com
MIST_API_TOKEN=<your-mist-api-token>
MIST_ORG_ID=<your-default-org-uuid>   # optional default for the org_id prompt
```

Loading is handled by the existing `python-dotenv` bootstrap in `MistHelper.py`.
The API token is consumed by `mistapi.APISession` and is never written to logs or
stdout. The returned `cli_commands` registration string is also never logged
(per the field-level logging policy in `data-model.md`).

## Expected output filenames

Files land under `data/` (the directory is enforced at runtime; create it with
`chmod -R 777 data/` on Linux first to satisfy the non-root container user).

- CSV: `data/org_<first-8-of-org-uuid>_aos_register_cmd.csv`
- SQLite: `data/mist_data.db`, table `org_aos_register_cmd`
- ArangoDB collection: `org_aos_register_cmd` (when polyglot backend is active)
- Redis key namespace: `mist:org:<org_id>:aos_register_cmd:<generated_at_utc>`

## Skeleton of the new method

The full implementation is generated by `/speckit.implement`; this skeleton
documents the expected shape so that inline comment and action logging coverage
can be reviewed before the code is written. Every executable line carries a `#`
comment (Constitution VI), and every meaningful action is bracketed by
`logging.info()` / `logging.debug()` calls (Constitution VII).

```python
class DeviceExportUtils:                                                            # existing class, no new wrapper

    def export_org_aos_register_cmd(self, org_id=None):                             # menu 58 entrypoint
        logging.info("Prompting for org_id for AOS register cmd menu item")         # before-prompt action log
        org_id = org_id or safe_input(                                              # honor caller override else prompt user
            "Org ID (UUID): ",                                                      # human-readable prompt text
            context="org_aos_register_cmd:org_id",                                  # SSH/container EOF context tag
            default=os.environ.get("MIST_ORG_ID", ""),                              # fall back to .env default
        )
        logging.info("Validating org_id %s", org_id)                                # before-validate action log
        if not is_valid_uuid(org_id):                                               # validate before any API call
            logging.warning("Invalid org_id %s -- aborting menu 58", org_id)        # log validation failure (no traceback)
            return                                                                  # early return per safety-first principle

        logging.info("Fetching AOS register command for org %s", org_id)            # before-API-call action log
        response = mistapi.api.v1.orgs.aos.register_cmd.getOrgAosRegisterCmd(       # actual SDK call
            self.apisession, org_id,                                                # only one path param; no query params
        )
        body = response.data or {}                                                  # normalize None to empty dict
        cli_commands = body.get("cli_commands", "")                                 # extract the one response field
        logging.debug(                                                              # after-API-call summary log -- NEVER log cli_commands itself
            "AOS register command returned: status=%s length=%d chars",
            response.status_code, len(cli_commands),
        )

        row = {                                                                     # build the single output row
            "org_id": org_id,                                                       # injected from prompt (API does not return it)
            "generated_at_utc": datetime.utcnow().isoformat() + "Z",                # client-side poll timestamp (part of UNIQUE key)
            "cli_commands": cli_commands,                                           # raw token string; persisted, never logged
            "cli_commands_length": len(cli_commands),                               # convenience length for queries
            "mist_host": os.environ.get("MIST_HOST", ""),                           # disambiguates multi-region deployments
            "http_status_code": response.status_code,                               # observability for error rows
        }

        logging.info("Writing AOS register command row via DataExporter")           # before-export action log
        DataExporter.write_with_format_selection(                                   # multi-backend write
            [row],                                                                  # list-of-rows interface (always one row)
            filename=f"org_{org_id[:8]}_aos_register_cmd",                          # human-friendly stem
            api_function_name="getOrgAosRegisterCmd",                               # PK strategy lookup key
        )
```

The method stays under 25 lines of executable code, takes <=2 parameters, and
contains <=4 logical blocks (prompt -> validate -> API call -> export). It lives
on the existing `DeviceExportUtils` class -- no standalone wrapper function.


The `--test` sweep automatically skips heavy/destructive operations (14, 18,
63-65, 90-100). Menu 58 sits inside the standard sweep range, so a green run
confirms the new item works end-to-end against the org configured in `.env`.

## Verification checklist

After running menu 58 once against a known org:

- [ ] `data/org_<first8>_aos_register_cmd.csv` exists and has exactly one row
      whose `cli_commands_length` matches the file's `cli_commands` cell length.
- [ ] `sqlite3 data/mist_data.db "SELECT COUNT(*) FROM org_aos_register_cmd;"`
      returns >= 1.
- [ ] Re-running the same menu within the same UTC second triggers the UNIQUE
      constraint guard (the second invocation either overwrites the row or is
      rejected, depending on DataExporter's configured `INSERT OR REPLACE`
      behavior; no duplicate rows ever appear).
- [ ] No log line at any level contains the `cli_commands` value or any substring
      of it (`grep -i "register-code\|challenge" data/script.log` returns empty).
- [ ] On an invalid org_id (non-UUID), MistHelper logs a `WARNING` and exits the
      menu cleanly with code 0 and no traceback.
