# Phase 1 Quickstart: adoptOrgJsiDevice

**Spec**: [spec.md](./spec.md)
**Plan**: [plan.md](./plan.md)
**Date**: 2026-06-28

This quickstart shows a developer how to run, exercise, and validate the new menu
item on a Windows 11 dev box. Container parity is identical (paths normalize via
`pathlib.Path` and `os.path.join`).

## Prerequisites

- Windows 11 with PowerShell 7+ (or any shell on Linux container).
- Python 3.13 or newer on PATH.
- Repository cloned at the worktree root referenced in `plan.md`.
- Working `.venv` activated:

  ```powershell
  .venv\Scripts\Activate.ps1
  ```

- `mistapi` 0.59+ installed:

  ```powershell
  python -m pip install --upgrade mistapi python-dotenv
  ```

## Required `.env` variables

Create or update `.env` in the repository root (git-ignored). Never commit this file.

```ini
MIST_HOST=api.mist.com
MIST_API_TOKEN=<your-mist-api-token>
MIST_ORG_ID=<your-default-org-uuid>   # optional default for the org_id prompt
```

Loading is handled by the existing `python-dotenv` bootstrap in `MistHelper.py`. The
API token is consumed by `mistapi.APISession` and is never written to logs or stdout.
The returned `cmd` payload is treated as sensitive and is never echoed to stdout or
logged at `INFO` or above -- only its length appears in the `DEBUG` summary line.

## Expected output filenames

Files land under `data/` (the directory is enforced at runtime; create it with
`chmod -R 777 data/` on Linux first to satisfy the non-root container user).

- CSV: `data/org_<first-8-of-org-uuid>_jsi_outbound_ssh_cmd.csv`
- SQLite: `data/mist_data.db`, table `org_jsi_outbound_ssh_cmd`

## Skeleton of the new method

The full implementation is generated by `/speckit.implement`; this skeleton documents
the expected shape so that inline-comment and action-logging coverage can be reviewed
before the code is written. Every executable line carries a `#` comment (Constitution
VI), and every meaningful action is bracketed by `logging.info()` / `logging.debug()`
calls (Constitution VII). The `cmd` content is never written to a log statement -- only
its length.

```python
class JsiExportUtils:                                                               # new (or reused) JSI export class

    def export_org_jsi_outbound_ssh_cmd(self, org_id=None):                         # menu 96 entrypoint
        logging.info("Prompting for org_id for JSI outbound SSH cmd menu item")     # before-prompt action log
        org_id = org_id or safe_input(                                              # honor caller override else prompt user
            "Org ID (UUID): ",                                                      # human-readable prompt text
            context="org_jsi_outbound_ssh_cmd:org_id",                              # SSH/container EOF context tag
            default=os.environ.get("MIST_ORG_ID", ""),                              # fall back to .env default
        )
        if not is_valid_uuid(org_id):                                               # validate before any API call
            logging.warning("Invalid org_id %s -- aborting menu 96", org_id)        # log validation failure (no traceback)
            return                                                                  # early return per safety-first principle

        logging.info("Fetching JSI outbound SSH cmd for org %s", org_id)            # before-API-call action log
        response = mistapi.api.v1.orgs.jsi.devices.outbound_ssh_cmd.adoptOrgJsiDevice(  # actual SDK call
            self.apisession, org_id,                                                # only org_id is required
        )
        body = response.data or {}                                                  # normalize None to empty dict
        cmd_string = body.get("cmd", "") or ""                                      # safe default if upstream returns null
        logging.debug("Received cmd length=%d", len(cmd_string))                    # length only -- never log cmd content

        logging.info("Flattening JSI outbound SSH cmd payload for org %s", org_id)  # before-flatten action log
        row = {                                                                     # single output row, org_id injected
            "org_id": org_id,                                                       # MistHelper context, not from body
            "cmd": cmd_string,                                                      # sensitive payload, persisted but never logged
            "cmd_length": len(cmd_string),                                          # convenience field for quick checks
            "polled_at_utc": datetime.now(timezone.utc).isoformat(),                # audit timestamp
        }
        logging.debug("Flattened 1 row")                                            # after-flatten count log

        logging.info("Writing JSI outbound SSH cmd via DataExporter")               # before-export action log
        DataExporter.write_with_format_selection(                                   # multi-backend write
            [row],                                                                  # list-of-rows interface
            filename=f"org_{org_id[:8]}_jsi_outbound_ssh_cmd",                      # human-friendly stem
            api_function_name="adoptOrgJsiDevice",                                  # PK strategy lookup key
        )
```

The method stays under 25 lines, takes 2 parameters (`self`, `org_id`), and has 4
logical blocks (prompt -> validate -> API call -> flatten + export) -- well inside
the 5-Item Rule budget.

## Quality gates (all must pass before commit)

Run these from the repository root with the venv active:

```powershell
python -m py_compile MistHelper.py        # 1. Syntax check (zero output = pass)
python -m ruff check MistHelper.py        # 2. Lint (zero violations = pass)
python -m black --check MistHelper.py     # 3. Format (zero diffs = pass; rerun without --check to auto-fix)
python MistHelper.py --test               # 4. Functional smoke test (menu 96 included)
```

The `--test` sweep automatically skips heavy/destructive operations (14, 18, 63-65,
90-100). Menu 96 sits just outside that skip range, so a green run confirms the new
item works end to end against the org configured in `.env`.
