### Collect EX switch hardware inventory into one CSV report (menu 309)

- **Added**: Menu 309 reads the profile of the credential and chooses one organization or every organization of an MSP. It previews the connected EX switches and asks for the typed phrase `RUN <count> TARGETS`. It then runs `show chassis hardware detail | display xml | no-more` on each switch and writes one CSV report with one row for each hardware item. A switch with no valid reply, and an organization that Mist could not read, appear as outcome rows. Issue #4920.
- **Added**: The Multi Site action **Collect EX hardware inventory** offers the output **One combined CSV report**. The preview shows the scope line, and the progress panel offers a download link when the report is complete. An MSP login covers every organization. Issue #4920.
- **Added**: The variable `PORTAL_WS_HARDWARE_CONCURRENCY` (default 3, range 1 to 5) limits the open shells of both actions. Issue #4920.
- **Added**: Menu 309 prints a note at step 1 when every grant of the credential has the read-only role, because Mist can refuse a switch shell for that role. A switch that Mist refuses gives an outcome row with the detail `The shell could not collect this switch. See the log for the cause.` Issue #4920.
- **Fixed**: A short file lock on Windows no longer fails a hardware run. A sync client or a virus scanner can hold the manifest of the run folder for a moment, and the replace then failed the whole batch. The store now tries the replace again, up to five times with waits of 50, 100, 200, and 400 milliseconds. A failed save now shows `The reply could not be saved.` in the report, and no longer shows `The reply was not a valid chassis inventory.` Issue #4926.
- **Changed**: The Multi Site action **Collect EX hardware inventory** keeps the Targets card. You choose all sites or some sites, and the preview says how many sites you chose. The server checks each site against the scope. Issue #4927.
- **Changed**: The review card of the Multi Site tab lists the four steps, names the confirmation word in the label and in the box, and tells you the next step above **Start batch**. Issue #4928.
- **Fixed**: `python MistHelper.py --web-portal` now resolves the organization before it builds the portal, so the WebSockets tab works on a workstation. Issue #4929.
- **Added**: The progress panel of the Multi Site tab shows the combined CSV report as a table when the report is complete. You can filter the rows, and you can move through a long report. The **Download CSV report** button stays. Issue #4931.
- **Fixed**: The page no longer opens the batch parent of a shell action as a terminal. The portal answered HTTP 409 twice, and the output panel showed `State: Connecting` for ever. The panel now shows the real state and the messages of the batch. Issue #4932.
