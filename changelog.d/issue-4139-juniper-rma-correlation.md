### Juniper service requests, RMA correlation, and asset coverage (menus 294 to 304)

- **Added**: Menu 301 checks Juniper service API access with one one-day read. Menu 302 correlates Mist support tickets with Juniper service requests and RMA details, and writes the exports. Menu 303 looks up one request or RMA. Menu 304 looks up warranty and contract data for serial numbers. The integration uses OAuth 2.0 client credentials over HTTPS and never sends a write operation to Juniper. Settings come from the local `.env` file. The `deploy/.env.example` file lists the names with placeholder values. Menus 294 to 297 read Juniper service requests: menu 294 lists the requests of a date window (Enter keeps the last 90 days), menu 295 reads one request with every field, menu 296 reads one RMA with its header and every item, and menu 297 reads the notes of one request. Menus 298 and 299 read the list of values and the software release list. Menu 300 reads asset bulk links for a date window of one to seven days old, and Juniper returns HTTP 401 until it enables the asset API for the application. Each menu prints every field and saves a CSV file under `data/`. Issue #4139.
- **Security**: Personal fields such as contact names, e-mail addresses, telephone numbers, and street lines are kept in full in the exports, by operator decision. The run log masks them in every line. Export files older than `JUNIPER_PII_RETENTION_DAYS` are removed at the start of each run. Free text such as the request synopsis keeps any e-mail address in the exports and masks it in the run log. A signed download link keeps only its scheme, host, and path.
- **Changed**: Menu 303 saves the RMA items to `JuniperLookupRmaItems.csv`. Before this change, the menu printed the items without a file. Issue #4139.
- **Changed**: When no Mist ticket matches a Juniper request, menu 302 logs one warning and writes a reason that names the cause: the Mist case numbers are not visible to the Juniper account of the app. Issue #4139.
- **Changed**: The Operations portal lists menus 294 to 304 under the Juniper RMA group. The portal asks each question in the order that the menu asks it, so the key type shows only the request number or the case number that it needs. A failed read states its reason in the status, for example an HTTP status, a connection error, or a timeout. A check that writes no file says so. The Execution Log wraps long values at word edges. Issue #4139.
