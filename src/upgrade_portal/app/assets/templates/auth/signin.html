{# auth/signin.html - the sign-in page of the upgrade capture portal. Why this file exists: FR-006 lets the operator choose between the environment API token and a managed service provider login. FR-007 then asks for the work address and the password. This page carries that whole choice, so no other page of the portal shows a credential field. Why the page holds a literal path: contracts/http-api.md fixes every public path of this portal. The blueprint endpoint names are not fixed in the template layer, so the form action follows the contract path. url_for stays for a static asset. Why the password field carries no value attribute: A value attribute would place the password in the markup. A refused attempt would then put it in the page source, in a screenshot, and in a browser cache entry. FR-009 forbids that, so the field always starts empty and the operator types the password again after a refusal. Why the cloud picker is a select and not a text field: The chosen host decides where the password travels. A text field would let a crafted post name any server. The route also checks the submitted host against the same catalog, so this control is the convenience and the route is the guard.
