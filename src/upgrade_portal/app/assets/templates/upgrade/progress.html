Why this file exists: contracts/http-api.md line 290 names GET /runs/ as the live run view with the phase list and the device table. This file is that view. The upgrade takes a long time, so the page must answer one question at a glance: what is the run doing now. The run state, the four cascade phases, and the state of each device therefore sit above every other detail. Why the page polls instead of streaming: The plan chose a 30-second poll over server-sent events, because the existing event bus stops at 10 subscribers. FR-039 asks for a refresh every 30 seconds. contracts/http-api.md line 262 repeats the same interval. The poll interval reaches the browser through data-poll-seconds, so an operator view and a test can use a different value without a code change. Why the page also holds a refresh button: FR-040 asks for a manual refresh. An operator who waits for a device to return does not want to wait 30 more seconds to see it.
