{# review/compare.html - the human view of one comparison. Why this file exists: contracts/http-api.md:341-343 states that GET /compare takes the same two query values as GET /api/comparisons and renders the human view. The two answers must report the same numbers, so this page prints what the route already decided and counts nothing on its own. Why the page holds one filter bar: contracts/ui-testids.md:25-26 states that a test identifier value appears once for each page. The word added names a device outcome and a client outcome, so two filter bars would print compare-filter-added twice. One bar holds the union of the two outcome sets, and the route hands the chosen outcome to the table that knows it. Why the filter controls are links: The content security policy of this portal is 'self' only, so an inline script would not run. A link needs no script, keeps the choice in the address bar, and lets the operator share the filtered view. Variables a route may supply: header - the two capture summaries, the site name, the organization name, and the skipped section list. devices - the device table. Holds rows, outcome, total, and skipped. clients - the client table. Holds rows, outcome, total, and skipped. statistics - the statistics region. Holds one record for each number. filters - one record for each filter control. Each record holds outcome, label, test_id, href, and active. csv_href - the address of the comma-separated value download. json_href - the address of the JSON download. page_title - the heading text and the tab text. theme - the name of the current theme.
