{# partials/lock_banner.html - the site lock banner of the upgrade capture portal. Why this file exists: FR-072 gives one site to one operator at a time. Every page that writes to a site therefore needs the same four answers: who holds the site, how long the wait lasts, how to take the site, and how to give it back. A partial holds those answers once, so the capture page, the options page, and the run page all show one banner and no route repeats the markup. Why the banner never blocks a read: contracts/site-lock.md line 159 states that a comparison page and a history page need no lock. This file is included by a page that writes, never by a page that reads. A read-only page that includes it anyway still renders, because every control below is a button and no control gates the content of the page. Why the banner holds no word of its own: FR-079 asks a different operator to type CONFIRM before a takeover erases in-flight data. FR-080 asks the same operator, returning to an abandoned session, to type continue instead. The two words differ, so the server names the needed word in details.needed_text on a confirmation_required refusal. portal.js writes that word into data-confirm-word and repaints the label. The value below is only the first guess, shown before any refusal arrives. Why the page holds no script: The content security policy is 'self' only. The policy blocks an inline script and blocks the style attribute. Every behavior lives in portal.js. The contract with portal.js: The banner carries data-lock-region and data-site-id. initLockBanner reads both. The take button carries data-lock-take. It posts to /api/sites//lock. A 400 confirmation_required opens the box below and writes the needed word. The submit button carries data-lock-confirm. It posts the same path with the typed word in the confirm field. The release button carries data-lock-release. It sends DELETE to the same path. The error region takes every refusal sentence. The heartbeat reads data-lock-token on the banner. An empty value means this browser holds no lock, so the beat does not run. Variables a route may supply: site_id - the site the banner covers.
